# ECHO NPC STUDIO 0.15

Первая рабочая версия нативного редактора NPC для Windows 10/11. Исходники — C++20; окно и события — Win32; 3D — Direct3D 11; собственный интерфейс — Direct2D и DirectWrite; PNG — WIC. Веб-компонентов, GUI-фреймворков и сторонних библиотек нет.

## Запуск

Готовая актуальная сборка: `dist/0.15/EchoNpcStudio.exe` (0.15). Переносите EXE вместе с папками `locales` и `templates`.

## Глубина слоёв лица

Проверены реальные ручные настройки: Саша и Отец используют Z 0 / 0.00001 / 0.0001 / 0.001 для белков / зрачков / век / бровей, Бен, Динара, Натан, Софа и Молли — 0 / 0.01 / 0.02 / 0.03. Универсальный сброс глубины редактора остаётся вариантом Бена, а поле Z позволяет сохранить свои значения.

Echo Animation 0.8.4 уменьшает authored Z в 1000 раз: маленькая глубина зрачка может совпасть с плоскостью белка после преобразования вершины во float. Исправление находится в **Echo Animation 0.8.5-SNAPSHOT**: к заданному Z добавляются отдельные плоскости для белков, зрачков, верхних/нижних век, бровей и очков. Предпросмотр Studio 0.13 использует те же интервалы. Изменения только в Studio не обновят уже загруженный Minecraft-мод: для игрового исправления замените старый echo-animation JAR новым и полностью перезапустите игру. Формат профилей не меняется, свои X/Y, Z и PNG перенастраивать не нужно.

В разделе «Портрет» X/Y относятся к портрету, Z — к 3D face rig. Кнопка **Настроить глубину слоёв** восстанавливает вариант Бена; Ctrl+Z отменяет действие. Для сохранения используйте **Сохранить в EchoScript**. Обычное сохранение профиля также записывает изменённую глубину в исходном rig; «Сохранить как» экспортирует выбранный профиль.

## Полное сохранение в EchoScript

Библиотека разделена на сворачиваемые группы **NPC с .npc.es** и **Без .npc.es · скины**. Наличие `.echo-npc` само по себе не означает наличие игрового NPC-скрипта. Поиск действует на обе группы.

Выберите NPC и нажмите **Сохранить в EchoScript** в свойствах или на нижней вкладке Echo Script. При наличии лица сохраняются имя, цвет, ссылка на скин в `.npc.es`, изменённые настройки глаз, бровей и век в `.face-rig.es`, настройки портрета в `.portrait-overlay.es`, скин и метаданные редактора. PNG слоёв остаются на своих игровых путях. Если лица ещё нет, откроется мастер текущего NPC: проверьте области глаз, бровей и верхних/нижних век и нажмите ту же кнопку в мастере. Он создаст весь набор без дублирования выбранного NPC. После успешного сохранения запись относится к группе с `.npc.es`; используйте Reload для повторной загрузки файлов с диска.

Существующий NPC-скрипт обновляется точечно: `Id`, `Display`, `Skin`, `NameColor`; комментарии и дополнительные свойства, включая `DefaultForm`, сохраняются. Исходная alpha цвета сохраняется. Внешнее изменение NPC-скрипта, rig, профиля или скина блокирует экспорт до Reload. Запись обновлений выполняется с резервными копиями и восстановлением при ошибке. Слои лица создаются в `assets/<namespace>/textures/echo_animation/faces/<id>/`, скрипты — в игровых каталогах `data/<namespace>/echo_npc/npcs/`, `echo_animation/face_rigs/` и каталоге профилей портрета.

Обычное **Сохранить** во вкладке Свойства сохраняет `.echo-npc`. Для полного игрового набора используйте **Сохранить в EchoScript**. Параметры Classic/Slim и переключатели внешних слоёв сохраняются в метаданных редактора; отдельные неподдерживаемые вызовы для них в NPC-скрипт не добавляются.

## Шаблон фонового NPC

В мастере создания лица и обычном окне создания NPC нажмите **Шаблон: фоновый NPC**. Кнопка заполняет имя «Незнакомец», нейтральный цвет имени `#DEC6B2` и свободный ID `jdh:background_00001`, `jdh:background_00002` и далее. Занятые ID библиотеки и существующие файлы назначения пропускаются. Скин, модель, папка назначения и разметка лица остаются выбранными вами; заполненные ID и имя можно редактировать до создания. В настройках уже существующего NPC эта кнопка не показывается.

Сам шаблон хранится в `templates/background.json` рядом с EXE:

```json
{
  "id_prefix": "jdh:background_",
  "display_name": "Незнакомец",
  "name_color": "#DEC6B2"
}
```

Эти значения относятся к игровому NPC и не меняются при переключении языка интерфейса. Изменения JSON применяются при следующем нажатии кнопки шаблона. Префикс должен быть допустимым плоским ID без вложенных папок, цвет — в формате `#RRGGBB`. Отсутствующий файл заменяется встроенным шаблоном; повреждённый файл показывает ошибку. После создания цвет имени можно выбрать из одежды в свойствах NPC.

## Локализация через JSON

Все собственные надписи интерфейса, кнопки, вкладки, подсказки, сообщения состояния, ошибки проверки данных и диалоги хранятся в `locales/ru.json` и `locales/en.json` рядом с EXE. Формат — плоский JSON-объект: стабильный ключ → строка в UTF-8. Значения можно менять без пересборки программы; изменения применяются при следующем запуске.

Язык по умолчанию — русский. В `locales/settings.json` укажите:

```json
{
  "language": "ru"
}
```

Для английского задайте `"en"`. Параметр запуска `EchoNpcStudio.exe --lang en` имеет приоритет над файлом настроек. Для нового языка скопируйте `en.json` в `<код>.json`, переведите значения и укажите этот код в настройках. Допустимы латинские буквы, цифры, дефис и подчёркивание. Пути локализации всегда считаются от папки EXE, независимо от рабочей папки ярлыка.

Примеры редактируемых ключей: `ui.common.save`, `ui.panels.properties`, `ui.facewizard.eyelids`, `ui.facewizard.thickness_pixels`. В строках с `{count}`, `{file}`, `{id}` и другими именованными параметрами сохраняйте имена параметров; их порядок можно менять. `\n` задаёт перенос строки. В фильтрах файлов сохраняйте шаблоны расширений и разделители `\u0000`.

Отсутствующие ключи берутся из встроенного русского словаря; английский имеет собственный встроенный запасной словарь. Повреждённый JSON отклоняется целиком, а предупреждение появляется в диагностике. Встроенные словари генерируются при сборке из тех же JSON. Тексты Windows и внешних драйверов зависят от языка системы; имена NPC берутся из игровых ресурсов, идентификаторы и синтаксис Echo Script не переводятся.

Версия 0.3 подключает существующие ресурсы **Echo Animation**. При обычном запуске автоматически открываются скины из указанного проекта PrismLauncher «Форма Мысли», если этот каталог существует. Также можно открыть папку скинов, корень content-pack или предоставленные каталоги `echo_animation/faces` / `data/jdh/echo_animation` через Open Folder. Связь определяется по настоящему ID face rig; для Player используется `echo_content_player:player/base`.

Слева доступны вкладки **Свойства | Портрет**. Версия 0.3 учитывает оба источника настроек: face rig из content-pack и `.portrait-overlay.es` из соседнего `story/configs`. Прежнее расхождение глаз возникало из-за отсутствия второго источника. Профиль задаёт Place, Scale, размеры, видимость и параметры моргания поверх face rig. Зрачки шириной один пиксель центрируются по правилам Minecraft GuiGraphics.

Верхняя строка очищена от повторного названия программы и индикатора D3D11. Убраны заголовок NPC LIBRARY и подпись папки. Кнопки **Свойства / Библиотека / Вкладки** справа вверху скрывают и возвращают соответствующие панели. Освободившееся место занимает модель или портрет; размеры панелей сохраняются в текущем сеансе.

В свойствах кнопка **«Слои скина»** сворачивает Hat/Jacket/Sleeves/Pants. По умолчанию блок свёрнут; это не выключает сами слои и не меняет NPC.

Кнопка **«Настройки лица…»** работает с выбранным NPC:

- Если face rig уже подключён, открывает его редактор портрета с существующими глазами, зрачками, бровями и веками. Позиции и размеры W/H доступны численно; границы видны на портрете. При наличии профиля W/H задают размер отображения портретного слоя, а исходные TextureArea X/Y остаются неизменными. Сохраняйте правки кнопкой сохранения профиля.
- Если слоёв ещё нет (например, исходный скин `jdh:2`), открывает разметку лица с текущим ID и кнопкой **«Сохранить лицо»**. Создаёт слои и rig для этого же NPC; запись библиотеки заменяется без дубликата. Исходное изображение сохраняется в `echo_animation/faces/<id>/source_skin.png`, текущий скин очищается от выбранных глаз/бровей после сохранения. Имеющийся NPC-скрипт сохраняется с его прочими свойствами; при отсутствии создаётся базовый скрипт.
- Отмена окна разметки ничего не записывает. Неожиданное изменение исходного скина требует Reload. Конфликт с существующими чужими ресурсами лица блокирует запись.

Для цвета имени нажмите **«Из одежды…»** в свойствах. В окне выбора показаны персонаж спереди, сзади и полная текстура. Нажатие на пиксель сразу переносит его RGB в Name Color и отмечает NPC изменённым. Прозрачный фон не выбирается. Учитываются включённые Hat/Jacket/Sleeves/Pants; цвет берётся без 3D-освещения. «Отмена» или Esc закрывают выбор без изменения цвета. После выбора используйте Save, либо создайте новый NPC с этим цветом через мастер.

В версии 0.5.1 исправлена разметка двухстрочных глаз с разными оттенками верхней и нижней строк. Переключение на разрез 2 px само расширяет короткую область в сторону соседней строки глаза; вручную увеличивать H перед переключением больше не требуется.

При закрытии окна с несохранёнными правками доступны «Сохранить и выйти», «Выйти без сохранения» и «Отмена». Выход без сохранения отбрасывает весь сеанс и работает даже с ошибочными значениями в полях. Без правок окно закрывается сразу.

Во вкладке **Портрет**:

- Статус «Профиль Minecraft подключён» означает, что используется существующий игровой профиль. Его путь виден внизу. При наличии каталога `echo_animation copy` обычный `echo_animation` имеет приоритет для одинакового ID.
- Выберите «Элемент», «Левый глаз», «Правый глаз», «Зрачки», «Брови» или «Всё лицо». Группа глаза включает белок, зрачок и обе половины век. Брови выбираются отдельной группой.
- Перетаскивайте элементы прямо на портрете либо используйте клавиши / кнопки стрелок. Шаг выбирается слева: **0.01 / 0.1 / 1 px**. По умолчанию 0.1 пикселя исходного лица; **Shift** уменьшает шаг и скорость перетаскивания в 10 раз. Числовые X/Y выбранного элемента доступны ниже списка после прокрутки.
- **Ctrl+Z** отменяет правку; **Ctrl+Y** или **Ctrl+Shift+Z** повторяет. Одно перетаскивание или движение группы — одно действие. История хранит до 200 действий для каждого rig и действует после сохранения. В активном текстовом поле Ctrl+Z отменяет ввод текста; Esc снимает фокус поля.
- «Сохранить профиль» и Ctrl+S изменяют `.portrait-overlay.es`, если профиль подключён. Позиции лица в 3D rig при этом не переписываются. При отсутствии профиля редактируются Position и TextureArea/Size в `.face-rig.es`; парные веки в таком rig двигаются вместе.
- Кружки рядом со слоями переключают видимость. В профиле она сохраняется как `visible`; без профиля это временный предпросмотр. Эти действия также можно отменять.
- «Моргание» использует параметры из профиля с fallback на rig. «Закрыть глаза» показывает крайнее состояние вручную.
- Сохранение меняет только нужные значения; комментарии, кавычки, форматирование и другие свойства сохраняются. Внешнее изменение исходника блокирует перезапись до Reload. Save As экспортирует копию профиля или rig; обычное обнаружение при следующем открытии относится к файлам в исходных игровых каталогах.
- Preview позволяет экспортировать составной PNG и скопировать исходник. Echo Script показывает редактируемый профиль либо rig. Assets перечисляет текстуры, профиль и связанные pose/animation файлы.
- 3D-модель рисует face rig отдельными текстурными плоскостями между основной поверхностью головы и Hat, с дробными координатами и порядком слоёв. Зрачки удерживаются внутри белков глаз по FaceLayerPoseProjector мода; слишком большие зрачки обрезаются. Портретные overrides применяются к портрету и миниатюрам, а не к мировому rig. Исходные PNG не меняются и не запекаются в увеличенный скин.

## Создание игрового NPC из скина

Выберите импортированный скин и нажмите **Создать NPC + лицо** сверху или **Create NPC** справа. Укажите новый уникальный ID, имя и корень content-pack. Для текущего проекта путь к pack подставляется автоматически.

Мастер автоматически определяет области белков, зрачков и бровей на лице 8×8. Ручная настройка:

- Выберите элемент кнопкой. Контрастные границы тёмные на светлых пикселях и светлые на тёмных, с дополнительной обводкой; активная область имеет восемь ручек. Такие границы используются и в готовом редакторе портрета.
- Тяните угол или сторону для изменения размера. Тяните внутри рамки для перемещения всей области. Переключатель «Новая рамка» позволяет заново нарисовать область; вне активной рамки также можно начать новую. «Все границы» скрывает/показывает остальные области.
- Поля **X / Y / Ширина / Высота** доступны для ручного ввода. Нажмите Enter или «Применить область». Координаты целые, от верхнего левого угла лица; размеры PNG соответствуют выбранной области.
- **Сила** задаёт чувствительность перетаскивания от 0.1 до 4, поддерживает точку или запятую. Быстрые кнопки: 0.25× / 1× / 2×. При 0.25× нужен вчетверо больший ход мыши для того же сдвига. Shift при начале перетаскивания дополнительно уменьшает силу вчетверо. Область привязана к целым пикселям, поэтому при медленном движении рамка ждёт накопления достаточного смещения.
- Рамка, поля, вырезаемые слои и собранное лицо обновляются во время движения. Области не выходят за лицо; зрачки остаются внутри глаза. Высота области глаза ограничена двумя пикселями, а парные глаза синхронизируют Y/высоту для совместных век.
- Ctrl+Z отменяет всю операцию, Ctrl+Y / Ctrl+Shift+Z повторяет. Кнопка ↶ также отменяет. В активном текстовом поле Ctrl+Z относится к вводу текста; снимите фокус нажатием на сетку, чтобы отменить изменение рамки.
- Брови можно отключить. «Образец кожи» позволяет выбрать цвет заполнения удалённых элементов.


Примеры Саши и Отца используются для разделения размера текстур и раскрытия век. «Саша · разрез 2 px» показывает две строки глаза; «Отец · разрез 1 px» закрывает часть глаза веками, сохраняя обе строки исходных зрачков. Если область была высотой один пиксель, выбор разреза 2 px расширит её до двух строк. Для настоящей текстуры высотой один пиксель задайте H=1 у области глаза. Предпросмотр обновляется до записи файлов.

Во вкладке **Веки** мастера верхние и нижние веки настраиваются отдельно:

Рамки и миниатюры показывают отдельный кусочек над/под каждым глазом. Ширина равна ширине соответствующего глаза: обычно 2 пикселя, толщина по умолчанию 1 пиксель. Для другой ширины измените W области глаза во вкладке «Глаза и брови». Между глазами и по краям лица маска век прозрачна; перетаскивание за промежуток между рамками не запускается.

- «Сдвиг по Y» — смещение в логических пикселях; доступны дробные значения. Рамку можно тянуть вертикально на исходном лице.
- «Толщина» — 1–4 пикселя. Верхнюю или нижнюю границу рамки можно перетаскивать для изменения толщины.
- «Ход моргания» — значение Travel игрового rig, от 0 до 250; 0 использует расчёт по выбранному разрезу глаза.
- «Закрытие для проверки» — от 0 до 1, только предпросмотр. Кнопки «Открыты»/«Закрыты» быстро меняют состояние. Предпросмотр не записывается как постоянное закрытие глаз.
- «Цвет век из кожи» включает выбор образца нажатием на исходное лицо; образец общий для верхних и нижних век.
- Ctrl+Z/Y отменяет/повторяет изменение. При создании сохраняются толщина PNG, положение в rig и portrait profile, а также Travel для каждой пары век.

Веки представлены парными слоями, как в исходных примерах проекта: обе верхние стороны используют общую настройку, обе нижние — свою.

Кнопка «Создать NPC» создаёт:

- новый очищенный скин и метаданные в `assets/<namespace>/textures/echo_npc/skins/<id>.png` / `.echo-npc`;
- белки, зрачки, брови и веки в `assets/<namespace>/textures/echo_animation/faces/<id>/`;
- копию исходника `source_skin.png` в этой же папке;
- `data/<namespace>/echo_npc/npcs/generated/<id>.npc.es` с ID, именем, скином и цветом;
- `data/<namespace>/echo_animation/face_rigs/generated/<id>.face-rig.es`;
- профиль `story/configs/<namespace>/echo_animation/portrait_overlays/generated/<id>.portrait-overlay.es`.

Новый NPC сразу появляется в библиотеке и редакторе портрета. Исходный скин сохраняется; существующие ресурсы не перезаписываются. При совпадении имени выберите другой ID. «Отмена» не создаёт файлов. После создания требуется штатная перезагрузка ресурсов/story в игре; проверка в запущенном Minecraft не выполнялась.

Автоопределение рассчитано на обычную раскладку глаз: перед созданием проверьте рамки. Для HD-скина используются логические пиксели лица 8×8; мелкие детали внутри одного логического пикселя не переносятся в отдельные слои. Второй слой головы остаётся в скине; мастер вырезает элементы основной поверхности лица. Полный экспорт обновляет поддерживаемые поля готового NPC-скрипта; при отсутствии выбранного скина прежний Create NPC создаёт метаданные редактора.

## Echo Script 2 и формат хранения

`.echo-npc` — **внутренний формат редактора**, а не EchoScript. Кнопка **Сохранить в EchoScript** записывает настоящий NPC-скрипт и связанные настройки лица и портрета. Поддерживается high-level NPC DSL `Id`, `Display`, `Skin`, `NameColor` и существующие high-level face rig / portrait overlay DSL из исходников игровых модов. Произвольный C#-код не редактируется; остальные блоки исходного NPC-скрипта сохраняются.

Пример собственного файла:

```text
ECHO_NPC_STUDIO 1
identifier "jdh:ben"
display "Бен"
skin "ben.png"
color "#DEC6B2"
slim "0"
hat "1"
jacket "1"
sleeves "1"
pants "1"
```

Другие ключи этого формата сохраняются при редактировании. Сопоставление папок и скинов задаётся выбором назначения при Create/Save As и заменой/копированием скина; фиксированная структура проекта не требуется.

## Игровые имена NPC

При сканировании читаются `Id`, `Display` и `NameColor` из настоящих `data/<namespace>/echo_npc/npcs/**/*.npc.es`. Поэтому в библиотеке и свойствах показываются Бен, Динара, Отец, Молли, Натан, Профессор Холден и остальные авторские имена. Явно сохранённые поля `.echo-npc` имеют приоритет. Если игрового определения нет, остаётся название PNG. Мастер создаёт базовый NPC-скрипт, а полный экспорт точечно обновляет его поддерживаемые поля. Из восьмизначного NameColor редактор берёт RGB, не меняя исходный alpha.

## Проверки

`EchoCoreTests` проверяет валидацию, UV всех шести сторон всех шести частей модели, Slim-геометрию, видимость слоёв, alpha compositing, PNG roundtrip через WIC, Unicode-пути и значения, сохранение неизвестных свойств, повторное обнаружение NPC с общим скином, кэш и операции текстового редактора.

Для проверки реального скина:

```powershell
& .\build\Release\EchoCoreTests.exe 'C:\Project\skins\ben.png'
```

Интеграционная проверка использует настоящий скрытый Win32-экземпляр приложения, GPU-рендеринг и обработчики интерфейса. Создаёт артефакты только в новой указанной папке, исходный каталог не изменяет. Проверяет сканирование, ввод русского имени, кнопку Save и чтение обратно, вращение мышью, Slim, портрет, маски глаз, resize, пересоздание устройства, Create NPC и асинхронный PNG drag-and-drop. Сохраняет PNG кадров и `passed.txt` либо `failure.txt`.

```powershell
.\scripts\Verify.ps1 -SkinFolder 'C:\Project\skins'
```

## Известные ограничения первой версии

- Полное редактирование произвольного Echo Script 2 не подключено. Мастер создания генерирует базовые NPC, face rig и portrait overlay скрипты по поддерживаемым шаблонам. Обычное Save сохраняет метаданные редактора; сохранение портрета меняет настоящий профиль или rig.
- Legacy 64×32 не конвертируется; формат явно отклоняется с диагностикой.
- Разметка глаз является эвристикой; требуется визуальная проверка. Face/Eye Editor доступен для скинов до 1024×1024. Экспортированные маски не подгружаются автоматически при повторном открытии редактора лица.
- Библиотека группирует NPC по папкам назначения; полноценного проводника произвольных файлов нет. Assets показывает основной скин и метаданные либо ресурсы Echo Animation в режиме Портрет.
- Подключён high-level face DSL `face Name("id")` с Eyes, Brows, Bone Glasses, Textures и Blink. Неизвестные верхние блоки и ресурсы старого низкоуровневого формата явно диагностируются. Pose/animation файлы обнаруживаются как связанные ресурсы; полноценное проигрывание их треков здесь не реализовано. Предпросмотр моргания учитывает Blink профиля и face rig.
- При подключённом профиле инспектор редактирует Place X/Y; Z и TextureArea доступны только для rig без профиля. Scale, размеры, глобальная проекция и остальные параметры профиля читаются и сохраняются, но отдельных полей для их изменения пока нет. Без профиля инспектор редактирует Position и TextureArea/Size. Pivot, Order, Texture и прочие свойства читаются/сохраняются, но отдельных полей для их изменения пока нет. При наличии Size без TextureArea смещение X/Y атласа остаётся нулевым.
- Автоматического наблюдения за внешними изменениями нет: используйте Reload. Изменения в открытой папке во время сканирования могут потребовать повторного сканирования.
- Кэш ограничен 512 MiB; большие наборы открывайте меньшими папками. Сканирование показывается целиком после завершения. Создание NPC, экспорт и копирование отдельных файлов пока синхронны.
- Для базовых поверхностей используется alpha исходного PNG. Исправление повреждённых/нестандартных скинов не выполняется. Никакая процедура не гарантирует правильную визуальную интерпретацию произвольной текстуры.
- Производительность 60 FPS на всех устройствах не заявляется как измеренная; idle ограничивается таймером около 60 Hz и VSync. Без анимации окно перерисовывается по событиям.
- Это первая рабочая версия, а не завершение всех расширенных требований исходного ТЗ.



## Удаление NPC

Выберите NPC в библиотеке и нажмите «Удалить…» либо используйте пункт удаления в контекстном меню. Можно удалить только .npc.es и метаданные, оставив скин в разделе без скрипта, либо также убрать скин, face rig, портретный профиль и текстуры лица. Файлы, используемые другими NPC текущей библиотеки, сохраняются. Общие анимации не удаляются. Перед операцией отображается точный список файлов. Несохранённые изменения удаляемого NPC отбрасываются.

Архив находится в `%LOCALAPPDATA%/EchoNpcStudio/DeletedNPCs`, вне игрового пакета. «Восстановить последнее удаление» возвращает файлы текущего сеанса без перезаписи существующих файлов. После перезапуска редактора файлы можно вернуть вручную: restore.txt в каждом архиве содержит исходные пути и имена резервных копий. Уже созданные сущности в запущенной игре удаляются средствами игры; эта операция редактирует ресурсный пакет.

В версии 0.15 направление вращения 3D-модели мышью инвертировано по горизонтали и вертикали.
