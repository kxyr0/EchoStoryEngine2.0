# а не arrival.
#
#
# Поэтому:
#
# DEPARTURE
# должен соответствовать reference.
#
#
# Arrival:
#
# сделать эстетически согласованным
# counterpart.
#
#
# Не утверждать,
# что arrival "в точности из видео".
#
#
# =====================================================================
# 27. ARRIVAL DEFAULT
# =====================================================================
#
# Destination:
#
# сначала:
#
# white/gold residual particles
# +
# concentrated golden light.
#
#
# Затем:
#
# local flash.
#
#
# На peak:
#
# entity становится visible.
#
#
# После:
#
# glow/particles fade.
#
#
# То есть:
#
# MATERIALIZATION,
#
# а не просто:
#
# instant entity pop.

# 28. VANISH API
# =====================================================================
#
# Полезно поддержать:
#
# TeleportMagic.Vanish(subject)

#
# Это:
#
# reference departure
# без destination arrival.
#
#
# После commit:
#
# конкретное gameplay действие
# должно быть explicit:
#
# despawn/hide/remove
#
# согласно existing actor lifecycle.
#
#
# Не silently kill entity.
#
#
# Если clean gameplay semantics
# для Vanish нет:
#
# оставить visual-only preview
# и не подделывать lifecycle.

# =====================================================================
#
# Поддержать:

# 35. PLAYBACK / EXECUTION ID
# =====================================================================
#
# Нужен typed:
#
# TeleportExecutionId.
#
#
# Resource/profile ID
# != execution ID.
#
#
# Два одновременных teleport

#

# =====================================================================
# 36. IMMUTABLE EXECUTION
# =====================================================================
#
# Teleport execution хранит минимум:
#
# execution ID
# subject ID
# source position
# destination
# server start tick
# visual seed
# phase
# commit state
# owner/root execution
# definition/profile revision.

# =====================================================================
# 37. DETERMINISTIC VISUAL SEED
# =====================================================================
#
# Server создаёт:
#
# deterministic random seed
# per TeleportExecution.
#
#
# Client uses it
# для particle generation.
#
#
# Не отправлять:
#
# 100 network packets
# на 100 particles.
#
#
# =====================================================================
# 38. NETWORK MODEL
# =====================================================================
#
# Packet/event:
#
# TELEPORT_VISUAL_START
#
# содержит:
#
# execution ID
# subject identity
# source position
# start tick
# seed
# visual profile version
# expected commit time.
#
#
# Client:
#
# локально воспроизводит timeline.
#
#
# =====================================================================
# 39. NO PARTICLE NETWORK SPAM
# =====================================================================
#
# Запрещено:
#
# server each tick
# →
# spawn particle packet × 50.
#
#
# Network:
#
# start
# commit/state correction if required
# cancel
# complete if required.
#
#
# Particle simulation:
#
# client-side.
#
#
# =====================================================================
# 40. VISUAL CLOCK
# =====================================================================
#
# Visual progression:
#
# deterministic elapsed time.
#
#
# Не зависит от FPS.
#
#
# 30 FPS
# 60 FPS
# 120 FPS
# 200 FPS
#
# должны давать
# одинаковую timeline duration.
#
#
# =====================================================================
# 41. TICK VS FRAME
# =====================================================================
#
# Gameplay commit:
#
# server tick.
#
#
# Visual interpolation:
#
# render partial tick / time.
#
#
# Поэтому:
#
# particles двигаются плавно
# даже при 20 TPS simulation.
#
