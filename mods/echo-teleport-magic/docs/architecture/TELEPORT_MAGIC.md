# Echo Teleport Magic — ETM1

Отдельный Forge 1.20.1 мод `echo_teleport_magic`, версия 0.1.0. Исходное задание сохранено в `requested-spec.txt`.
Модули: чистое Java-ядро, Forge runtime и отдельный development testmod. Testmod не устанавливается в Prism.

## Визуальная последовательность

Время отсчитывается от первых частиц. В revision 2 игровой commit назначен на 47-й серверный тик (2,35 с), полный эффект — 88 тиков (4,4 с). До commit визуальные часы плавно растянуты с эталонных 1,95 до 2,35 секунды, после него скорость хвоста сохранена. Таблица ниже использует эталонные визуальные часы.

| Время, с | Стадия | Поведение |
|---|---|---|
| 0–0,30 | Precharge | Несколько мягких жёлтых сфер |
| 0,30–1,20 | Buildup | Жёлто-золотые частицы кружатся около тела и накапливаются |
| 1,20–1,75 | Surge | Плотность и свечение текущей модели усиливаются |
| 1,75–2,15 | Concealment | Плотность золотого столба достигает пика |
| 1,95 | Commit | Сервер переносит субъект внутри вспышки |
| с 1,95 | Scatter | Накопленные частицы резко выбрасываются вверх и наружу |
| 2,15–2,80 | Afterburst | Источник сохраняет свет и частицы после переноса |
| 2,80–4,00 | Residual | Крупные сферы затухают раньше, последние жёлтые искры исчезают к концу |

Изменение после ручной проверки: частицы появляются с зазором от тела, кружатся на постоянном радиусе и накапливаются; стягивания к персонажу нет. Высота появления чередуется между тремя поясами, а верх столба постепенно растёт от 125% до 215% фактической высоты сущности. Посадка не уменьшает область искусственным множителем. В момент commit (1.95 с) добавляются 96 частиц и накопленное поле получает резкий выброс наружу с экспоненциальным замедлением и плавным затуханием. Рун, порталов, лучей и смены камеры нет.
Arrival — самостоятельный согласованный эффект материализации, а не утверждение о повторении отсутствующего в видео появления.

Выброс после ручной проверки усилен вдвое по горизонтальному и вертикальному импульсу. Направление каждого вылета отклоняется от радиуса на случайный угол до 0.65 рад, но всегда направлено наружу; скорость и вертикальный наклон различаются. Радиус появления дополнительно расширен на 12%; кружение до commit и количество частиц сохранены.

## Ответственность runtime

Сервер разрешает LivingEntity и существующую Location, проверяет размер, границы мира и коллизии, загружает FULL chunk и удерживает временный region ticket.
Cross-dimension, спящие субъекты и субъекты, несущие пассажиров, отклоняются до видимого эффекта.
Сам субъект может быть пассажиром: посадка сохраняется до commit, затем используется штатный `stopRiding()`.
До commit не меняются скин, форма, анимация, здоровье, инвентарь или система управления игроком.

Источник следует за субъектом до concealment, после commit получает неизменяемый anchor.
Arrival получает отдельный anchor. Уже выпущенные частицы остаются в мировых координатах.
Позиция, yaw, bounds, profile revision и seed зафиксированы в исполнении; Entity UUID не подменяет логический ActorId.
Scene execution, root owner и исходный файл/строка передаются отдельно от execution ID телепортации.

Для ServerPlayer используется `teleportTo(ServerLevel, ...)`. Для Echo NPC используется публичный `NpcService.teleport` с `ActorMutationId`.
Очередь NPC опрашивается по тому же mutation ID; повторного нового перемещения не создаётся.
Пока подтверждения нет, клиент удерживает concealment. Полный хвост продолжается после фактического подтверждения.
Отмена уже принятой асинхронной мутации ожидает подтверждения; обратного телепорта нет.

## Сохранение и восстановление

Квитанции в мировом каталоге `echo_teleport_magic/receipts`: BEFORE_COMMIT → COMMIT_INTENT → AFTER_COMMIT → COMPLETED.
Запись проходит через временный файл, `FileChannel.force(true)` и atomic move.
Подтверждённый commit не повторяется при повторной доставке Scene шага. Fingerprint использует логическую личность и конечную Location, а не временный UUID вновь материализованного NPC.
Неоднозначная COMMIT_INTENT после аварийного завершения отклоняется с `TELEPORT_RECOVERY_AMBIGUOUS`; слепого повторного переноса нет.
Это не атомарная транзакция между файловой квитанцией и Minecraft world save. Такой случай требует сверки состояния, а не обещания exactly-once при произвольном повреждении/откате сохранения.

## Сеть и рендер

Сеть передаёт START, COMMIT, CANCEL/COMPLETE и dev DEBUG, execution ID, Entity UUID, anchor, seed и start tick.
Сервер не отправляет пакет на каждую частицу. Получатели START запоминаются, чтобы CANCEL дошёл и после выхода из исходного радиуса.
Клиент ограничивает число активных полей, очищает их при смене мира/выходе и имеет аварийный timeout.

В одном atlas (640×128) находятся пять самостоятельно созданных radial textures. Золотая сфера совмещает свечение и светлый центр в одной текстуре: один quad вместо трёх. Все частицы имеют жёлтый ореол с небольшим светлым центром. Поле рисуется одним batch с depth test и отключённой записью depth.
Шейдер `soft_light` не отсекает alpha по порогу 0,1. Смешивание — SRC_ALPHA + ONE; external shaderpack не требуется.
Исправленная ранняя ошибка: ONE + ONE игнорировал прозрачность и превращал мягкие сферы в белые диски.
Пул света расположен на найденной поверхности; никаких графических знаков на нём нет.

Mixin на границе `EntityRenderDispatcher` дублирует уже преобразованные NEW_ENTITY vertices в emissive pass.
Повторного вычисления анимации и статического humanoid proxy нет; исходная геометрия и скин остаются на месте.
Это покрывает PlayerModel и текущий Echo NPC renderer, включая его стандартную текущую позу.
Произвольные сторонние модели с другим vertex format или вырезанной alpha-геометрией требуют отдельной проверки.
RenderType управляет setup/clear состояния; временные render buffers принадлежат эффекту.

Frustum/distance culling и дальний LOD меняют только плотность. Математика движения не зависит от FPS.

Траектории и размеры считаются в двух переиспользуемых массивах на 20 Гц и интерполируются на кадрах. Прозрачность остаётся аналитической на каждом кадре, чтобы не менять быстрое появление и затухание. Буферы, NPC reference, границы отсечения и результат неподвижной проверки земли переиспользуются. Частота появления увеличена примерно на 30%, размер — на 12%; бюджет остаётся 512 частиц.

Изолированный Java benchmark на одинаковом поле из 500 частиц: 800 кадров при сценарии 200 FPS, медиана 9 прогонов после прогрева — 10.197 мс для прежней математики и 4.752 мс для кеша (2.15×). Это сравнение CPU-расчёта частиц, не измерение общего FPS или GPU. Результат: `build/particle-motion-benchmark.json`. Ручной прогон сохраняет фактический профиль рендера в `run/etm-render-profile-manual.json` перед автозакрытием.

Ручной прогон с настоящим NPC после оптимизации завершён: 471 замер, пик 566 отрисованных частиц суммарно для источника и появления, CPU поля в среднем 0.159 мс, p95 0.457 мс; p95 интервала всего кадра 10.822 мс. Vanilla Forge на текущем компьютере, без shaderpack. Это один прогон, а не гарантия FPS на других сборках. Клиент штатно закрылся после действия.
Параметры частиц создаются один раз; в цикле вершин нет выделения Vector объектов.
First-person использует ту же временную шкалу и короткую тёплую экспозицию, без захвата камеры.

## Аудит соседних модов

| Мод | Использованная граница / вывод |
|---|---|
| echo-effects | Публичного world-bokeh/additive renderer нет; generic effect lifecycle не копируется |
| echo-npc | ActorId, NpcService, mutation receipts и публичный navigation body lookup |
| echo-animation / NPC animation adapter | Геометрия перехватывается после вычисления текущей позы |
| echo-player-actor | Владение управлением остаётся у Scene/Player Actor; второй control lock не создаётся |
| echo-scene | Generic parser/binder, typed ACTOR + LOCATION, DURABLE_BLOCKING, leases и durable step ID |
| echo-story-engine | Существующий запуск Scene; отдельного teleport parser/ExecuteAction нет |
| echo-script | Настоящий ES parser через SceneCompiler |
| echo-trigger / echo-events | Канонический каталог событий; добавлены пять TeleportMagic facts и journal codec |
| echo-content-doctor | Существующие Scene descriptors и source spans; отдельного scanner нет |
| echo-seating | Публичный bridge только для чтения; private internals не используются |
| echo-navigation | NPC body lookup не заменяет публичную durable NPC mutation |
| echo-time | HH:mm не используется для длительности VFX |

Репозитория `echo-story` нет; реально существует `echo-story-engine`.
Переиспользован существующий `sourceShapeCheck` из echo-effects; общего внешнего checker в workspace не найдено.
Все production Java/ES файлы ограничены 180 logical LOC, leaf packages — семью файлами.
SRP review: coordinator отвечает за state machine; Forge port — за платформенные side effects; длинный Brigadier register является декларацией дерева команд.

## Проверка

Сборка: `gradlew.bat build`. Dedicated smoke: `:teleport-magic-forge-1.20.1:runServer -PetmServerSmoke`.
Development capture: `:teleport-magic-forge-1.20.1:runClient -PetmSmoke`.
Ручной тест: добавить `-PetmManual`; R запускает действие, до нажатия эффект не начинается.
Опции `-PetmNpc -PetmSeated` подключают настоящий Echo NPC из development classes и сидячую fixture.
После полного ручного прогона клиент закрывается по запросу пользователя.
Кадры захватываются из world render event, а не HUD event: открывать Esc не требуется.
Ранний баг автотеста с пропуском стадий устранён явным состоянием armed; в журнал записываются заданное и фактическое время каждого кадра.

Точные результаты, runtime metrics, SHA-256 и ограничения live проверки фиксируются в `evidence/results.json` перед поставкой.
Unit tests сами по себе не доказывают совпадение с референсом. До полной проверки сохраняется статус `REFERENCE_VISUAL_MATCH_NOT_VERIFIED_LIVE`.
