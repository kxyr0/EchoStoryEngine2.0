# Echo Thought Space

`echo_thought_space` — непаузящее пространство мыслей: бесконечный 2D-холст, на котором завершённые Observation с `Thought(...)` становятся круглыми узлами.

## Открытие и закрытие

Клавиша по умолчанию — `P`, настраивается через Controls. Жизненный цикл:

```text
CLOSED -> OPENING -> OPEN -> CLOSING -> CLOSED
```

Открытие и закрытие проходят через настоящий чёрный кадр. Длительность задаёт `fadeMillis` в `config/echo-thought-space-client.toml`; значение по умолчанию `260`, допустимый диапазон `220..300` мс.

Экран не ставит мир на паузу. `P` закрывает пространство. `Esc` поглощается и не закрывает его, чтобы vanilla screen lifecycle не обрывал fade и input capture.

## Блокировка gameplay input

Input capture берётся на первом кадре открытия и освобождается только после последнего кадра закрытия. Пока Thought Space открывается, открыт или закрывается:

- движение игрока обнуляется;
- атака, использование предмета и горячие клавиши не проходят в мир;
- колесо не меняет hotbar, а масштабирует canvas относительно курсора;
- клавиатура и кнопки мыши поглощаются экраном;
- рабочими остаются `P`, курсор и перетаскивание холста ЛКМ.

Если в момент нажатия `P` уже открыт другой screen либо активна несовместимая cutscene, открытие отклоняется.

## Холст и камера

Thought Space использует отдельные canvas coordinates. Они не зависят от world camera, позиции игрока, разрешения окна или GUI Scale.

- Зажмите ЛКМ на пустом месте и ведите мышь, чтобы перемещать canvas camera.
- Потяните ЛКМ от одного круга к другому, чтобы проверить рецепт комбинации.
- Прокручивайте колесо, чтобы приближать и отдалять canvas. Логическая точка под курсором остаётся на месте.
- Наведение вычисляется круговым hit-test в физических пикселях.
- При перекрытии выбирается ближайший к курсору узел, затем более поздний в draw order.
- Узлы за пределами viewport отсекаются.
- Позиционные слоты сохраняются на текущую клиентскую сессию. При каждом новом открытии камера возвращается к центру и к `zoomInitial` из style DSL.

Новые ID получают детерминированные позиции по golden-angle spiral. Поэтому обновление текста или catalog revision не перемещает уже известный узел.

## Соединения и новые мысли

Обычный узел теперь рисуется одним контуром. Два внешних кольца были декоративным halo и удалены; при наведении меняются размер и яркость единственного контура.

Если начать drag на круге, за курсором тянется линия. При отпускании над другим кругом пара ID ищется в каталоге high-level ES2 declarations `Combination Name() { ... }` без учёта порядка: `A + B` и `B + A` эквивалентны.

- найденная комбинация открывает третий узел рядом с серединой пары, с боковым смещением в читаемый треугольник;
- после успеха остаются две постоянные линии: от каждого исходного узла к полученному результату;
- один результат не дублируется при повторной комбинации;
- открытый результат может участвовать в последующих рецептах;
- результат переживает refresh и повторное открытие полотна в текущей подключённой сессии;
- при отсутствии цели или рецепта линия за `280` мс возвращается к исходному кругу и затухает;
- logout очищает полученные комбинации, чтобы они не переносились между мирами.

Точные ID активных узлов выводит клиентская команда `/echo_thought_space list`.

## Внешний вид и zoom DSL

Внешний вид задают файлы `*.thought-space.es` внутри `story/configs`. Через них настраиваются начальный, минимальный и максимальный zoom, шаг колеса, радиус кругов, размер подписей узлов и опциональный неподвижный заголовок с координатами `x/y`.

Изменения применяются на открытом полотне примерно за `350` мс. Парсер запускается только когда изменились список файлов, timestamp или размер; рендер получает готовый immutable style и не разбирает DSL в кадре. Ошибочный hot reload не ломает экран: остаётся целиком последний успешно загруженный стиль.

Полный синтаксис style и рецептов: [Thought Space Config DSL](thought-space-config-dsl.md).

## Откуда берутся мысли

Встроенный optional Observation provider публикует только те точки, которые:

1. отмечены завершёнными для текущего игрока;
2. существуют в текущем Observation catalog;
3. содержат непустой `Thought(...)`.

Полный Observation ID становится стабильным ID узла, поэтому дубликаты не создаются. Изменение `Thought(...)` обновляет подпись существующего узла, сохраняя его позицию. `Text(...)` и `Dialogue.Load(...)` сами по себе узел не создают.

Если подходящих завершённых точек нет, показывается `Мыслей пока нет`.

## Важное отличие от completion overlay

`Text(...)` и `Thought(...)` независимы. Первый один раз показывается стандартной панелью Echo Dialogue, второй существует только как постоянная read-only подпись узла. Thought Space никогда не запускает completion overlay повторно.

## Команды диагностики

```text
/echo_thought_space status
/echo_thought_space list
/echo_thought_space debug on
/echo_thought_space debug off
```

- `status` выводит lifecycle state, число узлов, camera/zoom, revision конфига и активные размеры.
- `list` выводит точные ID и подписи всех доступных узлов, а затем все пары `input + input -> result`, включая ID ещё не открытых результатов.
- `debug on` включает canvas-диагностику координат, viewport и zoom.
- `debug off` выключает её.

Команды клиентские и не требуют прав оператора.

## Проверка контента

1. Создайте Observation с разными `Text(...)` и `Thought(...)`.
2. Активируйте resource и завершите точку через концентрацию.
3. Убедитесь, что completion overlay появился один раз.
4. Нажмите `P`: на холсте должен появиться один узел именно с `Thought(...)`, а не с `Text(...)`.
5. Измените `Thought(...)`, выполните `/echo_observation reload` и снова откройте Thought Space: подпись должна обновиться, позиция — остаться прежней.

Если узла нет, используйте `/echo_observation inspect "полный_id"` и проверьте completion, наличие `Thought(...)` и актуальность catalog.
