# Подготовка и публикация исходников

Этот документ предназначен для владельца проекта. Основной README описывает движок для посетителя репозитория.

## Подготовить новую копию

В рабочем каталоге разработки доступна локальная утилита:

```powershell
python tools/prepare_public_source.py --output ../EchoEngine-public-next
```

Утилита создаёт новую папку вне рабочего проекта и отказывается перезаписывать существующую. Сам файл утилиты не входит в публичную копию. Для этой команды нужна полная рабочая папка разработки.

Подготовка исключает вложенные Git-истории, локальные сборки, логи, кэши и резервные копии. Blender-дополнение копируется обычными файлами вместо локального соединения каталогов. Встроенные Content Credentials ресурсов сохраняются.

## Создать первый коммит

Создайте пустой репозиторий GitHub без автоматически добавленных README, лицензии и .gitignore. В подготовленной папке выполните команды ниже. Замените `OWNER` и `REPOSITORY` на владельца и название репозитория.

```powershell
git init -b main
git add .
git diff --cached --stat
git commit -m "Initial source import"
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

Порядок описан в [официальной инструкции GitHub](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github).

Перед первым коммитом проверьте список файлов и открытие ссылок README в подготовленной папке. Старые `.git` отдельных модулей в неё переносить не следует: публикация подготовлена как один репозиторий исходников.

## Следующие обновления

Сохраняйте опубликованную Git-историю. Новую подготовленную копию используйте как источник обновлённых файлов для того же репозитория; учитывайте также удаления и переименования. Не создавайте новую историю при каждом обновлении.

Версии модулей, изменения поведения и требования к зависимостям отражайте в документации соответствующей системы. Готовые сборки можно прикладывать к GitHub Releases отдельно от исходников.
