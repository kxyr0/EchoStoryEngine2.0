# Карта репозиториев

Какие модули владеют кодом, контентом и публичными API.

Эта страница фиксирует рабочий контракт раздела «Платформа»: какие ID должны оставаться стабильными, где проходит граница ответственности и что проверять при ошибке в контенте или состоянии во время игры.

## Контракт во время игры

- Долговечные ID должны быть логическими и иметь namespace.
- Сервер остаётся единственным источником состояния. Клиенты получают только снимки и изменения.
- Согласование должно быть идемпотентным: повторная проверка не перезапускает уже активное проигрывание.
- Диагностика ограничена по размеру, чтобы один сломанный ресурс не ломал соседних актёров.

## Что смотреть разработчику

- Проверьте ID из `.es` и путь файла в контент-паке.
- После правки выполните `/reload`.
- Смотрите профильную диагностику: `/echo_story diagnostics 20`, `/echo_dialogue diagnostics 20`, `/echo_npc diagnostics 20`, `/echo_animation diagnostics 20`.
- Если страница связана с адаптером, проверьте `/echo_story extensions` и соответствующий мост.

## Осмотр предметов

`echo-item-inspection` — самостоятельный мод `echo_item_inspection`: ПКМ по предмету
с `ItemInspectionResource` открывает клиентский viewer реального ItemStack. ЛКМ drag
вращает модель, колесо меняет масштаб, Esc возвращает к исходному inventory/container.
Опциональная интеграция с IPLA 6.3.1 находится в том же JAR: raycast выбирает
синхронизированный placed ItemStack, плавный prompt слева снизу показывает
назначенную клавишу (E по умолчанию), общий viewer возвращает прямо в gameplay.
Concentration, dialogue, cutscene camera и foreground screens имеют приоритет.

| Граница | Владелец |
|---|---|
| Определения и регистрация предметов | Minecraft / Echo Item Pack |
| ES2 inspection definitions, binding, LKG, presentation transform | `inspection-core` |
| Exact ItemStack snapshot, Screen, input, ItemRenderer | `inspection-forge-1.20.1` |
| Dev fixtures и dedicated GameTests | `inspection-testmod-1.20.1` |

Мод не зависит от Observation, Thought, Story или Item Attachments. Удаление его JAR
оставляет предметы и их владельцев работоспособными. Руководства находятся в
`echo-item-inspection/docs/architecture/ITEM_INSPECTION.md` и
`echo-item-inspection/docs/runtime/ITEM_INSPECTION_DSL.md`.
