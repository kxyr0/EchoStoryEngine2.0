## Как поддерживают README

Проверены по пять последних коммитов, затрагивавших README Godot, Bevy, Paper и Ink. Такая выборка показывает конкретные случаи сопровождения; она не доказывает наличие общего регламента или фиксированной периодичности.

- **Godot:** добавляет точки входа в экосистему, исправляет ссылки и убирает сломанные элементы. Примеры: [добавление Asset Store](https://github.com/godotengine/godot/commit/cabfd7bed1e23ed9d5ae775e38cb11c430fd0942), [удаление сломанного бейджа](https://github.com/godotengine/godot/commit/423326b25133cf9d3e8ae7eff9ceb32ed1a31b27).
- **Bevy:** поддерживает навигацию и представление страницы, в том числе удаляет элементы. Примеры: [исправление ссылки на RFC](https://github.com/bevyengine/bevy/commit/e6f39cb2d315d5b9327a3a6647310c4f4caf7002), [удаление CI-бейджа](https://github.com/bevyengine/bevy/commit/ba149c17a34e380cc7a4b89aadbe7efdbcbbc12b).
- **Paper:** обновляет индикаторы и ссылки при изменении ветки разработки. Примеры: [обновление статуса сборки](https://github.com/PaperMC/Paper/commit/c27ca36bf1d9d705e260f1cfb866c97de1ac537d), [исправление фильтра версии](https://github.com/PaperMC/Paper/commit/bd0c804a19b1cc1dd4b69b3138983c356d5c985d).
- **Ink:** синхронизирует примеры с API и обновляет инструкции среды. Примеры: [изменение имени свойства в примере](https://github.com/inkle/ink/commit/063b7d79c8ab126e7687c446be083548e26e3d32), [обновление инструкций Linux](https://github.com/inkle/ink/commit/83cd4ddac6556d84b9ec7eec751f8d72c55c9334).

Вывод для Echo: README стоит менять при изменении входа в проект — команд, требований, API примеров и структуры документации. Подробный журнал каждой правки удобнее хранить отдельно.

## Решения для нашего README

1. **Шапка:** название, короткое назначение, четыре справочных бейджа и переходы к главным разделам.
2. **Первый экран:** что делает движок и какую сцену с его помощью можно собрать.
3. **Статус:** активная разработка, независимые версии модулей и требования к их сочетанию.
4. **Возможности:** несколько смысловых групп вместо перечня всех папок.
5. **Начало работы:** отдельные маршруты автора контента и разработчика.
6. **Пример:** текущие формы EchoScript 2 для Story и Dialogue со ссылками на руководства.
7. **Модули и инструменты:** таблицы с реальными путями.
8. **Документация:** задача читателя сопоставлена с конкретной точкой входа.
9. **Авторство и лицензия:** фактическое положение проекта без заимствования условий других движков.

Команды первичной загрузки репозитория вынесены в [инструкцию публикации](PUBLISHING.md): они относятся к сопровождению исходников, а не к знакомству с движком.

## Что отложено

- Скриншоты и GIF: нужен собственный актуальный материал с понятным контекстом.
- Динамический статус CI и кнопки скачивания: адрес основного опубликованного репозитория и схема релизов ещё не закреплены в этой работе.
- Ссылка на сообщество: подтверждённый публичный канал не указан.
- Единый номер версии движка: проекты имеют собственные версии.
- Заявления о готовности к промышленной эксплуатации, производительности и полной переносимости: такие утверждения требуют отдельных проверок.

## Рекомендуемый порядок сопровождения

Это предложенный порядок для Echo Engine, а не уже действующая автоматизация:

- При изменении синтаксиса обновлять пример README и соответствующий шаблон вместе.
- При переименовании папок проверять относительные ссылки и дерево репозитория.
- При смене требований обновлять строки Java, Forge и соответствующего инструмента.
- Перед публикацией проверять команды на чистой среде; наличие команды в README само по себе не подтверждает успешную сборку.
- Добавлять бейдж при наличии действительного источника данных и убирать неработающие бейджи.
- Обновления поведения систем описывать в changelog, оставляя корневой README обзором проекта.
- Когда появится демонстрационный материал, разместить один показательный скриншот или короткий GIF после вводного описания.

GitHub рекомендует использовать README для назначения проекта, начала работы, помощи и сведений о сопровождающих. Относительные ссылки позволяют читать документацию в репозитории и в локальной копии. См. [официальное руководство GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes).
