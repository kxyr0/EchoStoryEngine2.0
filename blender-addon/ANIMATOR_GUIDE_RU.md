# ВАЖНО: режимы экспорта 3.1.0

В 3.1.0 обычные анимации больше **не обязаны** иметь Enter и Exit.

- **Разово** — экспортируется только Main, проигрывается один раз.
- **Цикл** — экспортируется только Main и runtime использует `LOOP_UNTIL_STOP`. Это штатный режим для `idle`, `walk`, `run`, `sprint`, `sneak`, `crawl`.
- **Hold** — экспортируется только Main; после последнего кадра runtime использует `HOLD_UNTIL_STOP` и держит позу до Stop. Не ставьте 100000 hold-тиков.
- **Фазы** — отдельный расширенный режим Enter → Main → Exit. Используйте его только если эти переходы действительно нужны.

Новые Action с именами idle/walk/run и родственными автоматически определяются как **Цикл**. Настройка режима хранится отдельно в самом Action и восстанавливается при следующем экспорте. Старые 3.0.x настройки автоматически мигрируются.

## Полное русское руководство для аниматора

Версия руководства: 1.0

Проверено в Blender: 5.2.0 LTS

Формат результата: процедурные ресурсы <code>.animation-clip.es</code> и <code>.animation.es</code>

---

## Для кого это руководство

Это руководство написано для аниматора, которому нужно сделать анимацию персонажа в Blender и передать её в Echo Story Engine.

Знать Java, EchoScript, устройство игрового runtime или программирование не требуется. От аниматора ожидается только базовое умение:

- выбрать Armature;
- перейти в Pose Mode;
- двигать и вращать кости;
- ставить ключевые кадры;
- пользоваться Timeline, Dope Sheet или Graph Editor;
- сохранить <code>.blend</code>.

Если вы впервые открыли этот add-on, начните с раздела «Быстрый старт за 5 минут». Если вы не знаете, какой тип анимации выбрать, откройте раздел «Как выбрать тип анимации».

Английские названия кнопок в руководстве сохранены, потому что именно так они отображаются в Blender. Рядом всегда дано русское объяснение.

---

## Самое важное в двух абзацах

Одна законченная Echo-анимация теперь всегда хранится в одном Blender Action. Если у движения есть начало, повторяемая середина и окончание, они не разбиваются на три отдельных Action. Они размещаются последовательно на одной временной шкале:

    0                 10                         34                 44
    |------ Enter -----|---------- Loop ----------|------ Exit ------|
                      ^                          ^
                 Loop Start                  Loop End

Границы являются общими кадрами. Кадр <code>Loop Start</code> одновременно завершает Enter и начинает Loop. Кадр <code>Loop End</code> одновременно завершает Loop и начинает Exit. Не нужно делать одинаковые кадры в разных Action и вручную синхронизировать их.

Перед экспортом всегда нажимайте <code>Validate Animation</code>. Ошибки блокируют экспорт. Предупреждения не блокируют экспорт, но их нужно прочитать и осознанно принять. После успешной проверки используйте <code>Generate Output Preview</code>, затем <code>Export Active Animation</code>.

# 1. Быстрый старт за 5 минут

Ниже — самый короткий правильный путь для обычной анимации.

## Шаг 1. Выберите скелет

В окне 3D Viewport выберите объект типа Armature. Выбирать меш персонажа недостаточно: активным объектом должен быть именно скелет.

Если add-on пишет <code>Select an Armature</code>, значит выбран не тот объект либо Armature вообще не выбрана.

## Шаг 2. Откройте панель Echo

1. Переключите любой редактор на <code>Dope Sheet</code>.
2. В левом верхнем выпадающем списке Dope Sheet выберите <code>Action Editor</code>.
3. Нажмите клавишу <code>N</code>, чтобы открыть правую боковую панель.
4. Откройте вкладку <code>Echo</code>.

Главная рабочая панель называется <code>Echo Animation</code>.

## Шаг 3. Создайте анимацию

Если Action ещё нет, нажмите <code>Create Animation</code>.

В диалоге укажите:

- <code>Action</code> — понятное имя Action в Blender, например <code>molly_idle</code>;
- <code>Resource ID</code> — игровой идентификатор, например <code>jdh:molly_idle</code>;
- <code>Rig</code> — обычно <code>jdh:humanoid</code>;
- <code>Animation Type</code> — тип поведения;
- <code>Start</code> и <code>End</code> — диапазон кадров.

## Шаг 4. Выберите пресет

После создания раскройте секцию <code>Animation</code>, выберите Preset и нажмите <code>Apply</code>. Для первой проверки выберите:

- <code>Idle Loop</code> для спокойного ожидания;
- <code>Walk Loop</code> для ходьбы;
- <code>One Shot</code> для одиночного жеста.

Пресет настраивает метаданные. Он не создаёт движение костей за вас.

## Шаг 5. Сделайте ключи

Перейдите в Pose Mode и анимируйте кости. Для обычного цикла:

1. Поставьте начальную позу на первом кадре цикла.
2. Сделайте промежуточные позы.
3. На последнем кадре цикла повторите начальную позу.

Для копирования начальной позы цикла в конец можно использовать <code>Copy Loop Start Pose to Loop End</code>, но эта кнопка заменяет позу и ключи в конце цикла. Перед использованием сохраните файл.

## Шаг 6. Укажите границы

Для цикла:

1. Перейдите на первый кадр цикла.
2. Нажмите <code>Set Loop Start</code>.
3. Перейдите на последний кадр цикла.
4. Нажмите <code>Set Loop End</code>.

Если вся анимация является циклом, нажмите <code>Use Full Action as Loop</code>.

## Шаг 7. Проверьте

1. В секции <code>Preview</code> нажмите <code>Loop</code>.
2. Посмотрите, нет ли рывка на стыке.
3. Нажмите <code>Validate Animation</code>.
4. Исправьте все строки с <code>[ERROR]</code>.
5. Прочитайте строки с <code>[WARNING]</code>.

## Шаг 8. Экспортируйте

1. Проверьте <code>Output Directory</code>.
2. Проверьте <code>Resource Folder</code>.
3. Нажмите <code>Generate Output Preview</code>.
4. Убедитесь, что показаны ожидаемые сегменты и пути.
5. Нажмите <code>Export Active Animation</code>.

## Шаг 9. Проверьте в игре

В игре с правами оператора:

    /echo_animation animations
    /echo_animation play_animation jdh:molly_idle jdh:molly

Остановить анимацию:

    /echo_animation stop_animation jdh:molly

Остановить только конкретную анимацию:

    /echo_animation stop_animation jdh:molly jdh:molly_idle

В этих командах сначала указывается ID анимации, затем ID NPC. У команды остановки порядок другой: сначала NPC, затем необязательный ID анимации.

# 2. Где находится интерфейс

## Основное рабочее место

Полный интерфейс находится здесь:

    Dope Sheet → Action Editor → Sidebar (N) → Echo

Почему именно Action Editor: метаданные Echo принадлежат конкретному Action. Когда вы переключаете Action, add-on автоматически показывает настройки именно выбранной анимации.

## Компактная панель в 3D Viewport

Короткая панель находится здесь:

    3D Viewport → Sidebar (N) → Echo → Echo Animation

В ней отображаются:

- имя активного Action;
- итог последней проверки;
- кнопка <code>Validate</code>;
- кнопка <code>Export</code>;
- кнопка создания анимации, если Action не настроен.

Компактная панель удобна для быстрой проверки, но полноценную настройку лучше делать в Action Editor.

## Панель Echo Rig and Skin

Работа со скелетом, скинингом, IK и моделью остаётся в:

    3D Viewport → Sidebar (N) → Echo → Echo Rig and Skin

Не путайте две задачи:

- <code>Echo Rig and Skin</code> готовит скелет и привязку меша;
- <code>Echo Animation</code> описывает временную шкалу, сегменты, события и экспорт движения.

## Настройки add-on

Общие настройки находятся здесь:

    Edit → Preferences → Add-ons → Echo Animation Exporter

### Default Output Directory

Папка экспорта по умолчанию. Она используется, когда собственное поле <code>Output Directory</code> активного Action оставлено пустым. В текущем проекте default уже указывает в live content pack Prism.

Изменяйте её, если:

- Prism instance перенесён;
- вы работаете с другим контент-паком;
- нужен отдельный тестовый output.

Если в Action уже записан собственный <code>Output Directory</code>, он имеет приоритет над default. Если поле Action пустое, изменение default сразу изменит вычисляемый путь его следующего экспорта.

### Default Resource Folder

Резервная стандартная подпапка, которая используется, если собственное поле <code>Resource Folder</code> Action пустое. Обычно Action уже содержит проектное значение, например:

    chapter_1/family

### Timeline Range Overlay

Включает ненавязчивые цветные полосы ENTER, LOOP, HOLD и EXIT в Action Editor. Это только визуальная подсказка. Источником границ остаются Action markers и Echo metadata.

Если overlay мешает видеть ключи, его можно выключить без влияния на экспорт.

### Enable Echo Marker Shortcuts

Включает необязательные горячие клавиши для границ. По умолчанию отключено, чтобы не конфликтовать с Blender keymap. Подробности находятся в разделе «Горячие клавиши».

# 3. Как устроена Echo-анимация

## 3.1. Один Action — одна полная анимация

Action — это контейнер ключей Blender. В новой системе один Action содержит всё поведение:

- вход в состояние, если он нужен;
- повторяемую часть, если она нужна;
- удерживаемую позу, если она нужна;
- выход из состояния, если он нужен;
- события;
- безопасные точки перехода;
- контакты стоп;
- настройки экспорта.

Новая система не создаёт отдельные файлы <code>name_enter</code>, <code>name_loop</code> и <code>name_exit</code>.

## 3.2. Метаданные принадлежат Action

Настройки Echo хранятся внутри самого Action:

- Resource ID;
- Rig ID;
- тип анимации;
- канал;
- диапазон;
- границы;
- Events;
- Points;
- Root Motion;
- параметры экспорта.

Это означает:

- разные Action не смешивают свои маркеры;
- переключение Action переключает и настройки;
- один и тот же Action можно назначить другому совместимому Armature;
- сцена не является источником правды для границ анимации.

## 3.3. Маркеры принадлежат Action

Echo использует Pose Markers Action, а не обычные Scene Markers.

В Action Editor они выглядят как отметки на временной шкале. Их можно передвигать. После передвижения проверка, preview и экспорт увидят новое положение.

Служебные имена начинаются с <code>ECHO_</code>. Видимые подписи объясняют смысл:

- Loop Start;
- Loop End;
- Hold Pose;
- Left Foot;
- Right Foot;
- Event;
- Point.

Не переименовывайте служебные маркеры вручную без необходимости. Для обычной работы используйте кнопки add-on.

## 3.4. Сегмент — это диапазон внутри Action

Сегмент не является отдельным Action и не является копией ключей. Это ссылка на диапазон общей временной шкалы.

Пример:

    Action: 0..44

    Enter: 0..10
    Loop:  10..34
    Exit:  34..44

Кадры 10 и 34 общие. Это сделано специально, чтобы переходы были детерминированными и не расходились из-за двух почти одинаковых поз.

## 3.5. Blender-кадры и игровые тики

Blender работает в кадрах. Echo Animation runtime работает в тиках. По умолчанию игровой темп — 20 тиков в секунду.

Add-on переводит всю временную шкалу одной общей формулой. Он не пересчитывает каждый ключ независимо и не растягивает разные сегменты по-разному.

Например, при 20 FPS Blender и 20 тиках в секунду:

- 1 Blender-кадр примерно равен 1 игровому тику;
- диапазон из 20 кадров длится примерно 1 секунду.

При 30 FPS Blender и 20 тиках в секунду некоторые соседние кадры попадут в один игровой тик. Validation предупредит об этом.

# 4. Как выбрать тип анимации

## 4.1. Быстрое дерево выбора

Ответьте по порядку.

### Вопрос 1. Движение должно повторяться?

- Нет — выбирайте <code>One Shot</code>.
- Нет, но после движения персонаж должен застыть в последней позе — <code>One Shot + Hold</code>.
- Да — переходите к вопросу 2.

### Вопрос 2. Повторяется вся временная шкала целиком?

- Да — <code>Loop</code>.
- Нет, есть отдельное начало и/или окончание — переходите к вопросу 3.

### Вопрос 3. В середине есть повторяемое движение?

- Да — <code>Stateful Loop</code>.
- Нет, в середине персонаж просто удерживает одну позу — <code>Stateful Hold</code>.

### Вопрос 4. Это ходьба, бег или другое перемещение?

- Да — <code>Locomotion</code>.
- Нет — оставьте <code>Stateful Loop</code>.

### Вопрос 5. Нужны нестандартные имена сегментов и ручная схема?

- Да — <code>Advanced</code>.
- Нет — используйте обычный тип. Advanced не нужен «на всякий случай».

## 4.2. Таблица выбора

| Что вы делаете | Тип | Обычно подходящий пресет |
|---|---|---|
| Взмах рукой один раз | One Shot | One Shot или Upper Body Gesture |
| Кивок, взгляд в сторону | One Shot | Look Direction |
| Спокойное дыхание | Loop | Idle Loop |
| Бесконечное вращение предмета | Loop | Idle Loop с ручной настройкой |
| Сесть, сидеть, затем встать | Stateful Loop | Sit |
| Лечь, спать, затем проснуться | Stateful Loop | Sleep |
| Подойти к стене, опереться и стоять | Stateful Hold | Lean Against Wall |
| Поднять предмет и удерживать его | Stateful Hold | Hold Object |
| Обычная циклическая ходьба | Locomotion | Walk Loop |
| Обычный циклический бег | Locomotion | Run Loop |
| Старт бега, цикл, остановка | Locomotion | Run with Start and Stop |
| Умереть и остаться лежать | One Shot + Hold | Death |
| Очень особая lifecycle-схема | Advanced | Ручная настройка |

## 4.3. Главное различие похожих типов

### Loop и Stateful Loop

<code>Loop</code> — повторяется вся анимация или выделенный цикл без отдельного жизненного цикла состояния.

<code>Stateful Loop</code> — персонаж входит в состояние, остаётся в повторяемом состоянии и затем выходит из него.

Пример:

- мерцание лампы — Loop;
- сесть, сидеть, встать — Stateful Loop.

### Stateful Loop и Stateful Hold

<code>Stateful Loop</code> имеет диапазон Loop, который проигрывается снова и снова.

<code>Stateful Hold</code> имеет один Hold Pose. Runtime удерживает один кадр, а не прокручивает фальшивый цикл длиной в один-два кадра.

Пример:

- дыхание во время сна — Stateful Loop;
- замереть, держа кнопку нажатой — Stateful Hold.

### One Shot и One Shot + Hold

<code>One Shot</code> проигрывается один раз и возвращает управление следующему состоянию.

<code>One Shot + Hold</code> проигрывается один раз и оставляет последнюю позу. Это подходит для смерти, падения без подъёма или необратимого сюжетного состояния.

# 5. Что подготовить до начала работы

## 5.1. Проверьте Armature

Для стандартного JDH humanoid используются экспортируемые кости:

- <code>root</code>;
- <code>body</code>;
- <code>head</code>;
- <code>left_shoulder</code>;
- <code>left_upper_arm</code>;
- <code>left_forearm</code>;
- <code>right_shoulder</code>;
- <code>right_upper_arm</code>;
- <code>right_forearm</code>;
- <code>left_thigh</code>;
- <code>left_shin</code>;
- <code>right_thigh</code>;
- <code>right_shin</code>.

IK-контроллеры можно анимировать для удобства, но сами control bones не являются runtime-костями. Экспортёр берёт вычисленную итоговую позу экспортируемых костей.

## 5.2. Проверьте имя Rig

Для текущего стандартного скелета используйте:

    jdh:humanoid

Не меняйте Rig ID только потому, что персонажа зовут по-другому. Rig ID описывает тип скелета, а не конкретного NPC.

## 5.3. Выберите FPS до анимации

Рекомендуемый простой вариант — 20 FPS, потому что Minecraft работает с 20 игровыми тиками в секунду.

Это не обязательное правило. Можно работать в 24, 25, 30 или 60 FPS, но:

- будет выполняться пересчёт;
- несколько Blender-кадров иногда попадут в один тик;
- потребуется внимательнее смотреть предупреждение <code>TICK_COLLISION</code>;
- очень мелкие движения между соседними кадрами могут не попасть в экспорт как отдельные моменты.

Не меняйте FPS в середине готовой работы без причины: визуальная скорость Action может измениться.

## 5.4. Примените трансформации объекта, если это часть вашего rig workflow

Перед началом сложной анимации убедитесь, что масштаб объекта Armature ожидаемый и не содержит случайного неравномерного масштаба.

Не применяйте трансформации к готовому production rig вслепую. Если скелет уже связан с мешем и проверен в игре, сохраните резервную копию перед изменением Object Transform.

## 5.5. Сохраните файл

Перед использованием миграции или кнопки <code>Copy Loop Start Pose to Loop End</code> сохраните <code>.blend</code>. Обе операции поддерживают Undo, но сохранённая версия остаётся самой надёжной страховкой.

# 6. Создание новой анимации

## 6.1. Кнопка Create Animation

Используйте <code>Create Animation</code>, если:

- вы начинаете новую работу;
- у Armature нет нужного Action;
- вы хотите новый независимый Action с чистыми Echo-метаданными.

Кнопка:

1. создаёт новый Action;
2. включает Fake User, чтобы Blender не удалил пустой Action после закрытия файла;
3. назначает Action активной Armature;
4. добавляет Echo-метаданные;
5. устанавливает диапазон;
6. применяет выбранный тип и пресет.

## 6.2. Как назвать Action

Имя Action нужно прежде всего человеку. Используйте понятную схему:

    персонаж_действие
    molly_idle
    molly_walk
    john_wave
    father_sit

Для общего движения, которое используют разные персонажи:

    humanoid_idle
    humanoid_walk
    humanoid_run

Не используйте имена вроде <code>Action.001</code>, <code>test2_final_new</code> и <code>aaaa</code> в production. Через месяц понять их назначение будет трудно.

## 6.3. Как назвать Resource ID

Resource ID имеет форму:

    namespace:path

Правильные примеры:

    jdh:molly_idle
    jdh:humanoid_walk
    jdh:chapter_1_father_sit

Неправильные примеры:

    molly_idle
    JDH:Molly Idle
    jdh:molly idle
    jdh:

Используйте только строчные латинские буквы, цифры и допустимые разделители. Кнопка <code>Normalize Names</code> умеет исправлять часть проблем, но лучше сразу писать чистое имя.

## 6.4. Action Start и Action End

Это полный экспортируемый диапазон.

Для One Shot это вся анимация.

Для Stateful-анимации это:

    Enter + Loop/Hold + Exit

Ключи вне диапазона не экспортируются. Validation покажет предупреждение, если такие ключи существуют.

# 7. Подключение старого Action

## 7.1. Кнопка Initialize Existing Action

Используйте <code>Initialize Existing Action</code>, если ключи уже находятся в одном Action, но он ещё не является Echo-анимацией.

Кнопка:

- добавляет метаданные к существующему Action;
- не удаляет ключи;
- не меняет позы;
- не объединяет другие Action;
- не создаёт искусственное движение.

После инициализации обязательно:

1. задайте правильный Resource ID;
2. выберите тип;
3. примените подходящий пресет или настройте поля вручную;
4. нажмите <code>Range from Keys</code>, если диапазон неверный;
5. расставьте границы;
6. выполните Validation.

## 7.2. Когда Initialize Existing Action не подходит

Если старое движение разбито на три Action:

- <code>run_enter</code>;
- <code>run_loop</code>;
- <code>run_exit</code>,

не инициализируйте их как три независимые новые анимации. Используйте секцию <code>Legacy Migration</code>, которая объединит их в один новый Action.

# 8. Полный справочник секции Animation

## Resource ID

Игровой идентификатор высокоуровневой анимации.

Пример:

    jdh:humanoid_run

Именно его вы передаёте в команду:

    /echo_animation play_animation jdh:humanoid_run jdh:molly

Resource ID должен быть уникальным. Если два Action экспортируются под одним ID в одну папку, последний экспорт может заменить предыдущий файл согласно Overwrite Policy.

## Rig

ID runtime-скелета, для которого сделана анимация.

Обычно:

    jdh:humanoid

Меняйте Rig только если технический специалист действительно добавил другой runtime rig.

## Animation Type

Определяет смысл временной шкалы и обязательные сегменты. Подробности находятся в следующем разделе.

## Preset

Готовый набор настроек. Выбор в списке сам по себе ничего не меняет. После выбора нажмите <code>Apply</code>.

Пресет меняет метаданные, но не меняет ключи костей.

## Channel

Определяет, какой участок тела контролирует анимация:

- Body;
- Upper Body;
- Lower Body;
- Head;
- Face;
- Custom.

Правильный канал позволяет сочетать несколько движений. Например, NPC может идти ногами и одновременно махать рукой верхней частью тела.

## Source State

Состояние до входа в анимацию.

Примеры:

- <code>idle</code>;
- <code>standing</code>;
- <code>walk</code>.

## Active State

Состояние, которое представляет центральная часть анимации.

Примеры:

- <code>sitting</code>;
- <code>sleeping</code>;
- <code>run</code>;
- <code>holding</code>.

## Target State

Состояние после выхода.

Часто:

    idle

Но может быть и другое, например переход из ходьбы сразу в бег.

## Return State

Куда логически возвращается One Shot после окончания.

Для жеста стоящего NPC обычно:

    idle

## Hold Last Frame

Удерживает последнюю позу One Shot.

Включайте для:

- смерти;
- необратимого падения;
- финального сюжетного кадра;
- позы, которая должна остаться до другой явной команды.

Не включайте для обычного взмаха рукой, если NPC после него должен вернуться к idle.

## Authored Speed

Скорость locomotion в блоках в секунду.

Это не FPS и не множитель анимации. Это смысловая скорость движения, для которой был нарисован цикл.

Пример:

- медленная ходьба: около 1–2 блоков/с;
- быстрый бег: больше;
- точное значение зависит от проекта и длины шага.

Если в Action есть осмысленное перемещение root, кнопку <code>Calculate from Root Motion</code> можно использовать для расчёта.

## Root Motion

Определяет обращение с перемещением root:

- Disabled;
- Extract;
- Preserve.

Подробный разбор находится в разделе Root Motion.

## Duplicate

Кнопка <code>Duplicate as New Echo Animation</code> создаёт копию Action с независимыми ключами и метаданными.

Используйте для варианта:

- walk → walk_tired;
- idle → idle_nervous;
- wave_left → wave_right после ручной доработки.

## Rename

Кнопка <code>Rename Action and Resource Together</code> помогает согласованно переименовать Action и Resource ID.

Используйте её вместо ручного изменения только одного имени, если хотите избежать путаницы.

## Reset

Кнопка <code>Reset Echo Metadata</code> сбрасывает настройки Echo. Ключи Action не являются целью этой кнопки, но после сброса параметры сегментов и экспорта потребуется настроить заново.

Операция требует подтверждения и поддерживает Undo.

## Copy Settings и Paste Settings

Копируют настройки Echo между Action.

Они полезны, если несколько анимаций имеют:

- одинаковый Rig;
- одинаковый тип;
- одинаковый канал;
- одинаковые параметры смешивания;
- одинаковую папку экспорта.

Ключи костей не копируются.

После вставки проверьте Resource ID и границы: слепо переносить имя и диапазоны между разными движениями опасно.

# 9. Все типы анимаций подробно

## 9.1. One Shot

### Что делает

Проигрывает Action один раз от начала до конца.

### Когда использовать

- жест;
- удар;
- кивок;
- поворот головы;
- взятие предмета без длительного удержания;
- короткая сюжетная реакция.

### Что требуется

- корректный Action Start;
- корректный Action End;
- ключи движения;
- Return State.

Loop Start и Loop End не нужны.

### Типичная шкала

    0                                               20
    |-------------------- One Shot ------------------|

## 9.2. Loop

### Что делает

Повторяет выбранный диапазон.

### Когда использовать

- idle;
- дыхание;
- повторяемое механическое движение;
- декоративная анимация без отдельного входа и выхода.

### Что требуется

- включённый Loop;
- Loop Start;
- Loop End;
- совпадающая поза на шве.

### Типичная шкала

    0                                               30
    |---------------------- Loop --------------------|
    ^                                                ^
    Loop Start                                  Loop End

Если весь Action является циклом, нажмите <code>Use Full Action as Loop</code>.

## 9.3. Stateful Loop

### Что делает

Позволяет:

1. войти в состояние;
2. повторять его центральную часть;
3. выйти из состояния.

Enter и Exit могут быть отключены, но Loop обязателен.

### Когда использовать

- сесть → сидеть → встать;
- лечь → спать с дыханием → проснуться;
- начать работать → повторять работу → закончить;
- открыть защитную стойку → держать живой цикл → закрыть.

### Типичная шкала

    0                 10                         34                 44
    |------ Enter -----|---------- Loop ----------|------ Exit ------|

## 9.4. Stateful Hold

### Что делает

Проигрывает Enter, затем удерживает одну выбранную позу, затем при остановке проигрывает Exit.

### Когда использовать

- опереться на стену и замереть;
- держать предмет неподвижно;
- нажимать кнопку и удерживать;
- принять статичную позу для диалога.

### Что требуется

- Hold Pose;
- при необходимости Enter;
- при необходимости Exit.

### Типичная шкала

    0                 12                         28
    |------ Enter -----|----------- Exit ---------|
                      ^
                  Hold Pose

Кадры между Hold и Exit могут содержать подготовку или быть частью авторской шкалы, но runtime удерживает именно указанную точку до запроса выхода.

Не создавайте искусственный loop из одного кадра. Для этого и существует Stateful Hold.

## 9.5. Locomotion

### Что делает

Описывает ходьбу, бег или другое циклическое перемещение.

Дополнительно поддерживает:

- Enter;
- Loop;
- Exit;
- контакты левой и правой стопы;
- Authored Speed;
- Root Motion.

### Когда использовать

- walk;
- run;
- sneak;
- тяжёлая походка;
- стилизованное циклическое перемещение.

### Что требуется

- Loop;
- Authored Speed желательно больше нуля;
- минимум один Left Contact;
- минимум один Right Contact;
- логичное чередование контактов;
- бесшовный цикл.

### Важная оговорка

Сам факт выбора Locomotion не заставляет NPC идти по миру. Анимация описывает позу, фазу шага, скорость и при необходимости root motion. Перемещение entity должен выполнять locomotion controller или другая игровая система.

## 9.6. One Shot + Hold

### Что делает

Проигрывает Action один раз и оставляет последний кадр.

### Когда использовать

- death;
- падение без подъёма;
- финальная поза кат-сцены;
- необратимое состояние.

### Когда не использовать

Не используйте вместо Stateful Hold, если позднее нужен красивый авторский Exit. One Shot + Hold не является схемой Enter → Hold → Exit.

## 9.7. Advanced

### Что делает

Даёт ручной контроль над именами Enter, Loop и Exit сегментов и lifecycle-параметрами.

### Когда использовать

- runtime-интеграция требует конкретных имён сегментов;
- стандартные смысловые имена не подходят;
- технический дизайнер дал точную схему.

### Когда не использовать

Не выбирайте Advanced только потому, что он звучит «мощнее». Для обычной ходьбы, сидения, жеста и idle стандартные типы безопаснее и понятнее.

Advanced по-прежнему использует общую Action и основные смысловые границы. Это не редактор произвольного количества независимых клипов.

# 10. Пресеты

## Главное правило

Пресет меняет только настройки и границы. Он не анимирует кости.

Если после нажатия <code>Apply</code> персонаж стоит неподвижно, это нормально. Пресет не является библиотекой motion capture.

## Idle Loop

Устанавливает:

- тип Loop;
- канал Body;
- состояние idle;
- мягкие значения blend.

Используйте для дыхания, переноса веса и небольших живых движений стоящего NPC.

## Walk Loop

Устанавливает:

- тип Locomotion;
- канал Body;
- состояние walk.

После применения добавьте контакты стоп и Authored Speed.

## Run Loop

То же назначение, что Walk Loop, но активное состояние run.

## Run with Start and Stop

Устанавливает Locomotion с Enter и Exit.

Используйте, когда в одном Action нарисованы:

- разгон;
- повторяемый бег;
- остановка.

## Sit

Устанавливает Stateful Loop:

- Enter включён;
- Loop включён;
- Exit включён;
- active state — sitting.

Подходит, если сидящий персонаж продолжает слегка дышать или двигаться.

## Sleep

Устанавливает Stateful Loop для сна. Центральный цикл может содержать дыхание.

## Lean Against Wall

Устанавливает Stateful Hold:

- вход в позу;
- удержание одного кадра;
- выход.

## Upper Body Gesture

Устанавливает One Shot на канале Upper Body.

Используйте, если ноги должны продолжать locomotion, пока руки и корпус выполняют жест.

## Look Direction

Устанавливает One Shot на канале Head.

Используйте для короткого поворота головы. Если нужно долго смотреть в сторону и затем вернуться по отдельной команде, лучше рассмотреть Stateful Hold с подходящим каналом.

## One Shot

Базовый одиночный Action на всём теле.

## Death

Устанавливает One Shot + Hold и удержание последнего кадра.

## Hold Object

Устанавливает Stateful Hold на Upper Body:

- поднять или принять позу;
- удерживать;
- опустить или выйти.

# 11. Timeline и игровые тики

## Action Start

Первый экспортируемый кадр.

## Action End

Последний экспортируемый кадр.

Action End должен быть строго больше Action Start.

## Blender FPS

Отображает фактический FPS сцены с учётом FPS Base.

## Engine Tick Rate

Число игровых тиков в секунду. Для Minecraft обычно:

    20

Без указания технического специалиста не меняйте это значение.

## Frames/tick

Показывает, сколько Blender-кадров приходится на один игровой тик.

Примеры:

- 20 FPS / 20 ticks = 1 кадр на тик;
- 30 FPS / 20 ticks = 1.5 кадра на тик;
- 60 FPS / 20 ticks = 3 кадра на тик.

## Export ticks

Итоговая длительность клипа в игровых тиках.

## Sample Every

Шаг семплирования вычисленной позы.

Значение <code>1</code> означает проверять каждый Blender-кадр диапазона.

Увеличение шага уменьшает число образцов, но может потерять:

- быстрый замах;
- короткий контакт;
- мелкое вторичное движение;
- результат constraint между редкими ключами.

Для production по умолчанию оставляйте <code>1</code>, если размер файла не стал доказанной проблемой.

## Duration Ticks

Если равно <code>0</code>, длительность рассчитывается по FPS Blender и Engine Tick Rate.

Ненулевое значение принудительно задаёт длительность в тиках и тем самым растягивает или сжимает всю Action.

Используйте вручную только если точно знаете требуемую игровую длительность.

## Previous и Next

Переходят к предыдущему или следующему Echo-маркеру в активном Action.

Удобно для быстрой проверки:

- Loop Start;
- Loop End;
- Hold;
- контактов стоп;
- Events;
- Points.

# 12. Segments и общие границы

## Use Full Action as Loop

Ставит:

    Loop Start = Action Start
    Loop End   = Action End

Используйте для обычного idle, walk loop или run loop, если Enter и Exit отсутствуют.

Не используйте, если в начале есть разгон, а в конце остановка: они случайно попадут в повтор.

## Set Loop Start

Ставит начало цикла на текущий кадр.

Для Stateful-анимации этот кадр также является концом Enter.

## Set Loop End

Ставит конец цикла на текущий кадр.

Для Stateful-анимации этот кадр также является началом Exit.

## Use Current Frame as Hold Pose

Ставит удерживаемую позу Stateful Hold на текущий кадр.

Выберите кадр, где:

- персонаж уже полностью пришёл в нужную позу;
- нет промежуточного движения;
- поза визуально стабильна;
- последующий Exit может корректно начаться из неё.

## Enter и Exit

Флажки включают соответствующие части.

Если Enter выключен, состояние начинается сразу с центральной части.

Если Exit выключен, остановка использует fallback-переход runtime вместо авторского Exit.

## Ручные имена сегментов в Advanced

Поля:

- Enter Segment;
- Loop Segment;
- Exit Segment.

Используйте латинские понятные идентификаторы без пробелов. Не задавайте одинаковое имя разным сегментам.

## Почему граница входит в оба соседних сегмента

Общий кадр гарантирует, что:

- конец Enter точно равен началу Loop;
- конец Loop точно равен началу Exit;
- нет скрытой разницы между двумя копиями одной позы;
- миграция не дублирует границы;
- переходы воспроизводятся предсказуемо.

# 13. Ключи на границах и бесшовный цикл

## Create Boundary Keys

Вставляет вычисленную позу в настроенные граничные кадры:

- Action Start;
- Loop Start;
- Loop End;
- Action End;
- Hold Pose, когда применимо.

Кнопка полезна, когда pose визуально существует из-за интерполяции или constraint, но явного ключа на границе нет.

## Only Animated Bones

Ставит граничные ключи только на кости, которые уже участвуют в Action.

Это рекомендуемый обычный режим:

- меньше лишних F-Curve;
- меньше случайной блокировки неиспользуемых частей;
- чище Action.

## All Exported Bones

Ставит ключи на все кости, разрешённые текущим каналом и маской.

Используйте, когда:

- нужен полностью зафиксированный boundary pose;
- сложные constraints дают неоднозначный результат;
- технический пайплайн требует явные ключи всех экспортируемых костей.

Минус: Action становится тяжелее и может начать контролировать кости, которые вы не собирались анимировать.

## Copy Loop Start Pose to Loop End

Копирует вычисленную позу Loop Start на Loop End и создаёт ключи.

Это самый прямой способ получить одинаковые крайние позы цикла.

Операция разрушительная для позы и ключей на Loop End. Перед нажатием:

1. сохраните файл;
2. убедитесь, что Loop Start и Loop End стоят правильно;
3. убедитесь, что в конце не должна быть уникальная поза;
4. после операции просмотрите движение перед швом;
5. при необходимости используйте Undo.

## Почему одинаковые крайние позы ещё не гарантируют красивый цикл

Даже если первый и последний кадр совпадают, рывок возможен из-за:

- неправильных tangents в Graph Editor;
- слишком большой скорости перед последним кадром;
- разной угловой скорости;
- контакта стопы, который меняется прямо на границе;
- вращения Эйлера через 360 градусов;
- constraint, который перескакивает;
- root drift.

Смотрите не только позу, но и несколько кадров до и после шва в циклическом preview.

## Loop Seam

Validation сравнивает Loop Start и Loop End по каждой экспортируемой кости:

- position;
- rotation;
- scale.

Если различие превышает tolerance, возникает ошибка <code>LOOP_SEAM</code>, а экспорт блокируется.

## Tolerance

Поля:

- Position Tolerance;
- Rotation Tolerance;
- Scale Tolerance.

Не увеличивайте tolerance, чтобы скрыть видимый рывок. Tolerance нужен для малой вычислительной погрешности, а не для оправдания разных поз.

Правильный порядок:

1. исправить ключи;
2. проверить constraints;
3. проверить Euler/quaternion continuity;
4. только потом слегка менять tolerance, если расхождение микроскопическое и визуально отсутствует.

# 14. Events и Points

## 14.1. Чем Event отличается от Point

<code>Event</code> — одноразовый сигнал в конкретный момент клипа.

<code>Point</code> — именованная безопасная или смысловая точка временной шкалы.

Проще:

- Event говорит «сейчас что-то произошло»;
- Point говорит «вот место, к которому можно привязаться или которое можно найти».

## 14.2. Add Event

Используйте для:

- шага со звуком;
- удара;
- открытия двери;
- взятия предмета;
- появления эффекта;
- момента синхронизации с сюжетным действием.

У Event есть:

- Name;
- Frame;
- Payload.

Payload — дополнительная строка для интеграции. Если никто не дал точный формат payload, не придумывайте сложный протокол. Уточните у технического дизайнера.

Важно: add-on экспортирует Event в клип. Конкретная игровая реакция на событие требует listener или интеграцию со стороны runtime/сюжета.

## 14.3. Add Point

Используйте для:

- безопасного выхода;
- neutral pose;
- точки синхронизации;
- момента, где другое действие может состыковаться;
- смысловой фазы движения.

У Point есть:

- Name;
- Frame;
- необязательный Segment.

## 14.4. Set Here

Перемещает выбранный Event или Point на текущий кадр.

## 14.5. Jump

Переходит на кадр выбранного элемента.

## 14.6. Delete

Удаляет элемент и связанный Action marker.

## 14.7. Контакты стоп

В Locomotion появляются специальные кнопки:

- <code>Left Contact</code>;
- <code>Right Contact</code>.

Контакт ставится в кадр, где соответствующая стопа:

- касается земли;
- принимает вес;
- перестаёт двигаться относительно поверхности на опорной фазе.

Для простого двухшагового цикла обычно есть минимум:

- один контакт левой стопы;
- один контакт правой стопы.

Контакты должны:

- находиться внутри Loop;
- логично чередоваться;
- не стоять обеими ногами на одном кадре без осознанной причины;
- не дублировать одну и ту же стопу одновременно на обоих общих краях цикла.

Если нужен второй контакт той же стопы, add-on создаст уникальное имя с суффиксом, например <code>left_foot_2</code>.

# 15. Каналы и маски костей

## Body

Контролирует всё стандартное тело.

Используйте для:

- full-body жеста;
- idle;
- walk/run;
- sit/sleep;
- death.

## Upper Body

Контролирует:

- body;
- head;
- плечи;
- верхние части рук;
- предплечья.

Не экспортирует ноги как часть этой анимации.

Используйте, чтобы поверх locomotion проиграть:

- взмах;
- указание рукой;
- разговорный жест;
- удержание предмета;
- верхнюю реакцию корпуса.

Если в Action есть ключи ног, Validation предупредит об этом. Эти ключи не будут контролировать ноги в runtime при данной маске.

## Lower Body

Контролирует root и ноги.

Используйте для специфической нижней анимации, которую нужно сочетать с независимой верхней.

## Head

Контролирует только head.

Используйте для:

- поворота головы;
- короткого наклона;
- взгляда в сторону, если движение глаз/лица обрабатывается отдельно.

## Face

Канал зарезервирован для лицевой части runtime. Текущий body-rig exporter ориентирован прежде всего на кости humanoid. Не используйте Face как замену отдельной системе лицевой анимации без согласованной схемы.

## Custom

Позволяет перечислить runtime-кости через запятую.

Пример:

    body, head, left_shoulder, left_upper_arm, left_forearm

Используйте только точные runtime-имена костей.

Custom нужен, когда стандартный канал захватывает слишком много или слишком мало. Для обычной full-body или upper-body работы он не обязателен.

## Что будет с анимированной костью вне маски

Validation покажет <code>OUTSIDE_MASK</code>. Ключи останутся в Blender Action, но эта кость не будет экспортирована данным каналом.

Это может быть:

- ожидаемо — например, вы временно оставили вспомогательные ключи;
- ошибкой — например, выбрали Head для жеста рукой.

# 16. Root Motion и Authored Speed

## 16.1. Что такое root motion

Root motion — перемещение главной кости <code>root</code> в пространстве во время анимации.

Пример: в Blender персонаж за 20 кадров физически сдвигается вперёд на длину шага.

Это отличается от in-place animation, где ноги двигаются, а root остаётся на месте.

## 16.2. Disabled

Перемещение root не используется как root motion, а NPC должен оставаться на месте относительно игрового владельца движения.

Выбирайте для:

- большинства in-place walk/run;
- idle;
- жестов;
- сидения на заранее заданной позиции;
- первой простой проверки анимации.

Если root заметно уезжает, Validation покажет <code>ROOT_DRIFT</code>.

Не игнорируйте root drift автоматически. Часто это случайно поставленный ключ location.

## 16.3. Extract

Экспортирует движение root отдельно как RootMotion metadata и root track. Runtime sampler отделяет его от локальной позы кости.

Выбирайте, если:

- locomotion pipeline умеет потреблять extracted root motion;
- длина шага должна определять перемещение;
- технический дизайнер подтвердил поддержку.

Сам exporter не двигает Minecraft entity. Извлечённое движение должен применить игровой locomotion owner.

## 16.4. Preserve

Оставляет движение в обычном bone track.

Выбирайте только если runtime owner понимает bone-driven displacement. Validation специально выдаёт предупреждение, потому что без соответствующего владельца визуальный меш и entity могут разойтись.

## 16.5. Root Bone

Обычно:

    root

Кость должна существовать в экспортируемом rig.

## 16.6. Calculate from Root Motion

Рассчитывает Authored Speed по перемещению root между Loop Start и Loop End и длительности цикла.

Кнопка:

- не изменяет Action;
- не двигает кости;
- только вычисляет значение скорости.

Если цикл in-place и root не перемещается, результат будет нулевым или бесполезным. В таком случае Authored Speed вводится вручную по проектной скорости.

## 16.7. Как выбрать между in-place и root motion

Если вам никто не дал отдельное требование, используйте in-place:

- root на месте;
- Root Motion = Disabled;
- Authored Speed задана вручную;
- entity двигается игровой locomotion-системой.

Root motion требует согласованной технической поддержки и не является автоматическим улучшением качества.

# 17. Preview

## Full Action

Проигрывает весь диапазон Action от начала до конца.

Используйте для общего просмотра постановки.

## Preview One Shot

Проигрывает One Shot так, как он описан текущим типом.

## Enter

Проигрывает только входной сегмент.

Если Enter отключён или отсутствует, результат может быть пустым или не иметь смысловой длительности.

## Loop

Повторяет только центральный цикл.

Это главный режим для поиска рывка на шве.

## Exit

Проигрывает только выход.

## Enter → Loop

Проигрывает Enter, затем переходит к повторению Loop.

Проверьте:

- нет ли остановки на границе;
- совпадает ли скорость тела;
- не перескакивает ли опорная нога;
- логично ли начинается цикл.

## Loop → Exit

Запускает Loop, а затем запрашивает Exit на границе цикла.

Этот режим показывает, как выход начинается из повторяемой фазы.

## Stop

Останавливает custom preview и восстанавливает:

- исходный frame range;
- preview range;
- текущий кадр;
- sync mode.

Add-on также старается восстановить эти значения при ошибке или отмене.

## Важное ограничение Preview

Blender preview не симулирует визуальный crossfade runtime. Переход между фазами показывается жёстко по границе.

Поля Blend In, Blend Out и Fallback Blend экспортируются, но окончательно их качество нужно проверять в игре.

# 18. Validation

## 18.1. Когда нажимать Validate Animation

Нажимайте:

- после расстановки границ;
- после изменения диапазона;
- после смены типа;
- после изменения канала;
- после редактирования Loop Start или Loop End;
- перед каждым экспортом;
- после копирования настроек;
- после миграции;
- после исправления шва.

## 18.2. Статусы

### Valid

Ошибок и предупреждений нет.

### Warning

Экспорт разрешён, но есть условия, которые нужно проверить.

Warning не означает «всё точно нормально». Он означает «система не может решить за аниматора».

### Invalid

Есть минимум одна ошибка. Экспорт блокируется.

### Not Initialized

Action ещё не подключён к Echo. Нажмите <code>Initialize Existing Action</code> либо создайте новый.

## 18.3. Быстрые исправления

### Range from Keys

Выставляет Action Start и Action End по существующим ключам.

Используйте после импорта или для старого Action.

После применения перепроверьте границы: крайний случайный ключ может расширить диапазон слишком далеко.

### Clamp Markers

Перемещает маркеры, вышедшие за диапазон, внутрь Action Start..Action End.

Это безопаснее ручного поиска, но смысл границы всё равно нужно проверить.

### Normalize Names

Приводит Resource ID и имена к допустимой форме.

После применения проверьте, что Resource ID остался понятным и уникальным.

### Remove Duplicates

Удаляет дублирующиеся Echo-маркеры.

## 18.4. Select Problem Bones

Если Loop Seam указывает конкретные кости, кнопка выбирает их в Pose Mode.

После выбора:

1. откройте Graph Editor;
2. сравните ключи на Loop Start и Loop End;
3. проверьте position, rotation и scale;
4. исправьте кривые;
5. снова запустите Validation.

## 18.5. Справочник сообщений

### NOT_INITIALIZED

Action не настроен как Echo Animation.

Решение: <code>Initialize Existing Action</code>.

### RESOURCE_ID

Resource ID имеет неправильную форму.

Решение: используйте <code>namespace:path</code> и <code>Normalize Names</code>.

### RIG_ID

Rig ID имеет неправильную форму.

Обычно исправление:

    jdh:humanoid

### FRAME_RANGE

Action End меньше либо равен Action Start.

Решение: задайте реальный положительный диапазон или нажмите <code>Range from Keys</code>.

### DUPLICATE_MARKER

Один служебный marker существует несколько раз.

Решение: <code>Remove Duplicates</code>, затем перепроверьте границы.

### MARKER_RANGE

Marker находится вне экспортируемого диапазона.

Решение: переместить вручную, изменить range либо нажать <code>Clamp Markers</code>.

### BOUNDARY_ORDER

Loop Start находится после Loop End.

Решение: переставить границы.

### HOLD_RANGE

Hold Pose находится вне Action.

Решение: выберите правильный кадр и нажмите <code>Use Current Frame as Hold Pose</code>.

### LOOP_REQUIRED

Выбран тип, которому нужен Loop, но Loop выключен.

Решение: включить Loop и поставить границы либо выбрать другой тип.

### ZERO_SEGMENT

После перевода в тики сегмент имеет нулевую длительность.

Причины:

- границы стоят на одном кадре;
- слишком короткий сегмент;
- соседние Blender-кадры попали в один тик;
- принудительный Duration Ticks слишком мал.

Решение: раздвинуть границы или увеличить общую длительность.

### DUPLICATE_SEGMENT

Два сегмента имеют одинаковое имя.

Решение: изменить ручные имена в Advanced или нормализовать state names.

### SPEED_MISSING

Для Locomotion не задана Authored Speed.

Решение: ввести блоки/с вручную или рассчитать по Root Motion.

### FOOT_CONTACTS

Нет контакта одной или обеих стоп.

Решение: поставить минимум Left Contact и Right Contact внутри Loop.

### FOOT_OUTSIDE_LOOP

Контакт стопы находится за пределами Loop.

Решение: перенести контакт или исправить границы цикла.

### FOOT_OVERLAP

Левая и правая стопа отмечены на одном кадре.

Это может быть допустимо при прыжке или стойке, но для обычной ходьбы чаще является ошибкой разметки.

### FOOT_ORDER

Контакты не чередуются.

Проверьте порядок L → R → L → R.

### FOOT_BOUNDARY_DUPLICATE

Одна и та же стопа отмечена и на Loop Start, и на Loop End. Поскольку границы общие, это может быть двойным описанием одного контакта.

### ROOT_BONE

Указанная Root Bone не входит в runtime rig.

Решение: обычно установить <code>root</code>.

### OUTPUT_PATH

Output Directory указывает не на папку.

Решение: выбрать существующую или создаваемую директорию контент-пака.

### UNKNOWN_BONE

Action анимирует control bone или неизвестную кость, которая не экспортируется.

Это нормально для IK-контроллера, если итоговые production bones вычисляются корректно. Но неизвестное имя может также означать ошибку rig.

### OUTSIDE_MASK

Экспортируемая кость анимирована, но исключена текущим Channel.

Решение: выбрать правильный Channel или Custom mask.

### UPPER_BODY_LEGS

Upper Body Action содержит ключи ног.

Решение: удалить ненужные ключи ног или выбрать Body, если ноги действительно должны контролироваться.

### FCURVE_MODIFIERS

Есть F-Curve modifiers.

Экспорт использует вычисленную позу, поэтому результат может быть корректным, но его необходимо внимательно preview и проверить в игре.

### KEYS_OUTSIDE

Есть ключи вне Action Start..Action End.

Решение: расширить диапазон или удалить случайные внешние ключи.

### BOUNDARY_KEYS

На одной или нескольких границах нет явного ключа.

Решение: <code>Create Boundary Keys</code>.

### SCALE_TRACKS

В Action анимируется scale.

Это информационное сообщение. Проверьте, действительно ли runtime rig ожидает scale-анимацию. Неравномерный scale часто даёт некрасивое сжатие конечностей.

### FRAME_RATE

FPS Blender отличается от Engine Tick Rate.

Это информация о пересчёте, а не обязательная ошибка.

### TICK_COLLISION

Несколько Blender-кадров попадают в один игровой тик.

Граничные кадры получают приоритет, но мелкое движение может потерять отдельный момент. Проверьте результат в игре.

### LOOP_SEAM

Начальная и конечная позы Loop различаются сильнее tolerance.

Validation укажет:

- имя кости;
- разницу position;
- разницу rotation;
- разницу scale;
- номера кадров.

Исправляйте ключи, а не только tolerance.

### ROOT_DRIFT

Root движется, хотя Root Motion выключен.

Решение: убрать случайное перемещение root или осознанно выбрать Extract/Preserve.

### ROOT_PRESERVE

Preserve требует runtime owner, который поддерживает такое перемещение.

Это техническое предупреждение. Уточните интеграцию.

# 19. Export

## 19.1. Output Directory

Корневая папка Echo Animation внутри контент-пака. В текущей Prism-установке проекта стандартный путь:

    C:\Users\kxyr0\AppData\Roaming\PrismLauncher\instances\Форма Мысли\minecraft\story\content-pack\jdh\echo_animation

Внутри неё exporter создаёт:

    animation_clips
    animations

Если Prism instance переименован или перенесён, выберите новый путь вручную.

## 19.2. Resource Folder

Подпапка хранения внутри <code>animation_clips</code> и <code>animations</code>.

Пример:

    chapter_1/family

Результат:

    animation_clips/chapter_1/family/molly_idle.animation-clip.es
    animations/chapter_1/family/molly_idle.animation.es

Resource Folder влияет на расположение файлов, но runtime Resource ID остаётся тем, что записано в поле Resource ID.

Не помещайте в Resource Folder имя файла или расширение.

## 19.3. Export Animation Resource

Если включено, exporter создаёт оба файла:

- низкоуровневый clip;
- высокоуровневую animation resource.

Для обычного аниматора флажок следует оставить включённым.

Выключайте только по точной просьбе технического специалиста, если нужен один clip.

## 19.4. Overwrite Policy

### Overwrite Generated Files

Рекомендуемый production-режим.

Exporter заменяет только файл, в котором есть заголовок:

    // GENERATED BY ECHO BLENDER ADD-ON.
    // MANUAL CHANGES MAY BE OVERWRITTEN.

Ручной файл без заголовка защищён: exporter откажется его перезаписывать.

### Ask Before Overwrite

При существующем файле требует подтверждения.

Удобно при ручной проверке, но замедляет batch export.

### Never Overwrite Existing

Никогда не заменяет существующие файлы.

Используйте для безопасного пробного экспорта в папку, где уже есть production-ресурсы.

## 19.5. Generate Output Preview

Строит результат в памяти, но не записывает файлы.

После выполнения:

- в панели показываются сегменты;
- показываются целевые пути;
- в Blender Text Editor создаются тексты:
  - <code>Echo Generated Clip.es</code>;
  - <code>Echo Generated Animation.es</code>.

Используйте перед первым экспортом каждой новой анимации.

## 19.6. Copy Generated .es

Копирует сгенерированный EchoScript в буфер обмена.

Это удобно для:

- отправки техническому специалисту;
- сравнения;
- вставки в issue;
- быстрой диагностики.

Не редактируйте generated output как основной способ исправления анимации. Источник правды — Blender Action и его метаданные.

## 19.7. Export Active Animation

Порядок работы:

1. запускает validation;
2. блокируется при errors;
3. строит чистую модель экспорта;
4. сериализует clip;
5. сериализует animation resource;
6. записывает через временный соседний файл;
7. атомарно заменяет целевой файл согласно Overwrite Policy.

## 19.8. Open Output Folder

Открывает целевую папку в Проводнике Windows.

Используйте после экспорта, если нужно убедиться в наличии файлов или передать их вручную.

## 19.9. Что находится в clip

Файл <code>.animation-clip.es</code> содержит:

- Id;
- Rig;
- Duration;
- Segments;
- Loop;
- Points;
- Events;
- bone Tracks;
- Keys;
- interpolation;
- authored speed;
- RootMotion metadata, если применимо.

## 19.10. Что находится в animation resource

Файл <code>.animation.es</code> содержит высокоуровневое поведение:

- Channel;
- State;
- ссылку на Clip;
- Enter;
- Loop;
- Hold;
- OneShot;
- Exit;
- BlendIn;
- BlendOut;
- Fallback.

## 20.1. Куда установлен add-on

## 20.3. Как убедиться, что runtime видит ресурсы

Запустите instance <code>Форма Мысли</code>, войдите в мир и выполните:

    /echo_animation health

Команда показывает количество загруженных rigs, clips, animations и diagnostics.

Посмотреть известные high-level animations:

    /echo_animation animations

Посмотреть clips:

    /echo_animation body_clips

Посмотреть rigs:

    /echo_animation body_rigs

Посмотреть последние ошибки загрузки:

    /echo_animation diagnostics

Больше строк диагностики:

    /echo_animation diagnostics 50

## 20.4. Как проиграть анимацию на NPC

Формат:

    /echo_animation play_animation <animation_id> <npc_id>

Пример:

    /echo_animation play_animation jdh:humanoid_run jdh:molly

Если NPC имеет другой ID, замените <code>jdh:molly</code>.

Команда требует права уровня оператора.

## 20.5. Как остановить

Остановить текущую Echo-анимацию NPC:

    /echo_animation stop_animation jdh:molly

Остановить только конкретную анимацию:

    /echo_animation stop_animation jdh:molly jdh:humanoid_run

## 20.6. Если новая версия файла не появилась в игре

Действуйте по порядку:

1. Убедитесь, что экспорт был в папку именно запущенного instance.
2. Нажмите <code>Open Output Folder</code>.
3. Проверьте время изменения обоих файлов.
4. Выполните <code>/echo_animation diagnostics 50</code>.
5. Проверьте <code>/echo_animation animations</code>.
6. Если runtime watcher не подхватил изменение, перезайдите в мир или перезапустите instance.
7. Убедитесь, что Resource ID в команде совпадает с полем Blender, а не только с именем Action.

## 20.7. Если команда пишет NPC actor not found

Проблема не в анимации. Runtime не нашёл NPC с указанным ID.

Проверьте:

- точный namespace;
- точное имя NPC;
- существует ли NPC в текущем мире;
- не используете ли отображаемое имя вместо Actor ID.

## 20.8. Если анимация есть в catalog, но не играет

Проверьте:

1. <code>/echo_animation diagnostics 50</code>;
2. совпадает ли Rig ID анимации с rig/profile NPC;
3. правильный ли Channel;
4. не удерживает ли канал другая приоритетная анимация;
5. не экспортирован ли пустой канал из-за маски;
6. есть ли реальные bone tracks в generated clip.

# 21. Пошаговые рецепты

## 21.1. Простой Idle

### Настройки

- Preset: Idle Loop;
- Type: Loop;
- Channel: Body;
- Root Motion: Disabled;
- весь Action как Loop.

### Процесс

1. Создайте Action <code>humanoid_idle</code>.
2. Поставьте диапазон, например 0..40.
3. Нажмите <code>Apply</code> у Idle Loop.
4. Нажмите <code>Use Full Action as Loop</code>.
5. На кадре 0 сделайте нейтральную позу.
6. На кадре 20 добавьте лёгкое дыхание и перенос веса.
7. Скопируйте позу кадра 0 на кадр 40.
8. Смягчите кривые в Graph Editor.
9. В секции Preview запустите <code>Loop</code>.
10. Выполните Validation.

### Что не делать

- не раскачивайте весь корпус одинаковой синусоидой;
- не двигайте root по земле;
- не делайте слишком сильное дыхание;
- не оставляйте разные позы на кадрах 0 и 40.

## 21.2. Одиночный жест рукой поверх ходьбы

### Настройки

- Preset: Upper Body Gesture;
- Type: One Shot;
- Channel: Upper Body;
- Return State: idle или состояние, заданное проектом.

### Процесс

1. Сделайте нейтральную верхнюю позу на первом кадре.
2. Нарисуйте подготовку руки.
3. Сделайте основную фазу жеста.
4. Верните верх тела к совместимой нейтральной позе.
5. Не ставьте ключи ног без необходимости.
6. Выполните Preview One Shot.
7. Убедитесь, что начало и конец не дают резкого скачка поверх locomotion.

## 21.3. Поворот головы

### Настройки

- Preset: Look Direction;
- Type: One Shot;
- Channel: Head.

### Процесс

1. Первый кадр — исходная ориентация head.
2. Несколько кадров — плавный поворот.
3. При обычном One Shot верните голову к исходной ориентации.
4. Если нужно остаться в повороте, выберите Stateful Hold, а не бесконечно длинный One Shot.

## 21.4. Ходьба in-place

### Настройки

- Preset: Walk Loop;
- Type: Locomotion;
- Channel: Body;
- Root Motion: Disabled;
- Authored Speed: проектное значение;
- Loop на всю Action или выделенный цикл.

### Классические фазы

Для одного полного цикла:

1. Contact левой;
2. Down;
3. Passing;
4. Up;
5. Contact правой;
6. Down;
7. Passing;
8. Up;
9. возврат к Contact левой.

### Процесс

1. Сделайте полный цикл.
2. Скопируйте первую позу на последний кадр.
3. Поставьте Left Contact на первую опору левой.
4. Поставьте Right Contact на опору правой.
5. Если первый и последний кадр описывают один и тот же контакт, не создавайте два смысловых дубля одной стопы без необходимости.
6. Проверьте стопы сбоку и спереди.
7. В секции Preview просмотрите <code>Loop</code> минимум несколько повторов.
8. Validation.
9. Проверка в игре на фактической скорости NPC.

### Если стопы скользят

Проверьте:

- Authored Speed соответствует длине шага;
- контакты стоят в правильных кадрах;
- стопа в опорной фазе не движется назад/вперёд относительно мира;
- runtime entity speed не отличается от authored speed;
- root не дрейфует при Disabled.

## 21.5. Бег со стартом и остановкой

### Настройки

- Preset: Run with Start and Stop;
- Type: Locomotion;
- Enter: включён;
- Loop: включён;
- Exit: включён.

### Пример диапазона

    Action:     0..44
    Enter:      0..10
    Loop:      10..34
    Exit:      34..44

### Процесс

1. На 0 персонаж в исходном состоянии.
2. На 10 он приходит в первую точную позу бегового цикла.
3. Кадры 10..34 образуют бесшовный бег.
4. Кадр 34 совпадает с кадром 10 по loop pose.
5. С 34 начинается остановка.
6. Поставьте Loop Start = 10.
7. Поставьте Loop End = 34.
8. Добавьте foot contacts внутри 10..34.
9. В секции Preview проверьте <code>Enter → Loop</code>.
10. В секции Preview проверьте <code>Loop → Exit</code>.
11. Validation.

## 21.6. Сесть, посидеть, встать

### Настройки

- Preset: Sit;
- Type: Stateful Loop;
- Source State: idle;
- Active State: sitting;
- Target State: idle.

### Процесс

1. Enter: стоя → сидя.
2. Loop: небольшое дыхание в сидячей позе.
3. Exit: сидя → стоя.
4. Loop Start — первый полностью сидячий кадр.
5. Loop End — совпадающий сидячий кадр перед вставанием.
6. Проверьте положение таза и стоп на общих границах.
7. Если посадка привязана к стулу, проверьте в игре реальное расположение NPC относительно стула.

## 21.7. Опереться на стену

### Настройки

- Preset: Lean Against Wall;
- Type: Stateful Hold.

### Процесс

1. Сделайте Enter из исходной позы в опору.
2. На точном устойчивом кадре нажмите <code>Use Current Frame as Hold Pose</code>.
3. От этого же состояния сделайте Exit.
4. В секции Preview проверьте <code>Enter</code>.
5. Убедитесь, что Hold Pose не является промежуточной позой.
6. В секции Preview проверьте <code>Exit</code>.
7. Проверьте в игре расстояние до стены.

## 21.8. Смерть

### Настройки

- Preset: Death;
- Type: One Shot + Hold;
- Channel: Body;
- Hold Last Frame: включён.

### Процесс

1. Начните с совместимой живой позы.
2. Сделайте падение.
3. Последний кадр — стабильная финальная поза.
4. Не делайте Exit.
5. Проверьте, что последняя поза не содержит очевидного пересечения с полом.
6. Проверяйте в игре с реальной коллизией и положением entity.

## 21.9. Держать предмет

### Настройки

- Preset: Hold Object;
- Type: Stateful Hold;
- Channel: Upper Body.

### Процесс

1. Enter подводит руку к предмету.
2. Hold Pose точно совмещает кисть и attachment/socket.
3. Exit уводит руку.
4. Добавьте Event в момент фактического захвата, если игровая интеграция привязывает предмет по событию.
5. Добавьте Event в момент отпускания, если это требуется.
6. Согласуйте event names и payload с программистом.

# 22. Пакетный экспорт

## Export All Echo Animations

Кнопка обрабатывает все Action, у которых включён <code>Echo Animation Enabled</code>.

Для каждого Action она:

1. выполняет validation;
2. экспортирует valid Action;
3. экспортирует Action с warnings;
4. пропускает invalid Action;
5. продолжает обработку остальных;
6. собирает итоговый отчёт.

Внизу панели появляется summary:

- сколько exported;
- сколько содержало warnings;
- сколько failed.

Каждая ошибка также выводится в системную консоль Blender.

## Перед batch export

1. Сохраните <code>.blend</code>.
2. Убедитесь, что у всех Action уникальные Resource ID.
3. Проверьте Output Directory.
4. Используйте Overwrite Generated Files.
5. По возможности заранее валидируйте каждый Action.
6. После batch прочитайте не только число exported, но и список failed.

Batch не должен останавливаться из-за одной плохой анимации. Это сделано специально, чтобы одна ошибка не блокировала весь набор.

# 23. Миграция старых Enter, Loop и Exit Action

## Когда нужна Legacy Migration

Используйте, если старый проект хранит:

- отдельный Enter Action;
- отдельный Loop Action;
- отдельный Exit Action.

Новая система должна получить один Action.

## Поля

- Enter Action — необязательный;
- Loop Action — обязательный;
- Exit Action — необязательный;
- New Action — имя результата;
- Source State;
- Active State;
- Target State.

## Preview Migration

Ничего не изменяет. Показывает:

- будущий диапазон;
- границы;
- несовпадающие кости на местах склейки;
- итоговое имя.

Всегда запускайте Preview Migration до Merge.

## Merge to New Action

Создаёт новый Action и запекает вычисленные позы.

Операция:

- сохраняет исходные Action;
- не удаляет старые данные;
- пропускает дублированные общие boundary frames;
- переносит доступную интерполяцию;
- создаёт Action-local метаданные;
- добавляет neutral transition point;
- назначает новый Action Armature.

## После миграции

1. Не удаляйте исходники сразу.
2. В секции Preview проверьте <code>Full Action</code>.
3. Проверьте <code>Enter → Loop</code>.
4. Проверьте <code>Loop → Exit</code>.
5. Выполните Validation.
6. Исправьте Loop Seam.
7. Проверьте Resource ID.
8. Экспортируйте под новым именем.
9. Проверьте в игре.
10. Только после подтверждения архивируйте legacy Actions.

# 24. Копирование, дублирование и управление Action

## Echo Actions

В верхней части панели показан список Action. Рядом с каждым отображается значок последнего статуса.

Кнопка справа активирует Action на выбранной Armature.

Список показывает первые доступные Action и предназначен для быстрого переключения, а не для полного управления Blender datablocks.

## Duplicate as New Echo Animation

Создаёт независимую копию.

После дублирования сразу поменяйте:

- Action name;
- Resource ID;
- при необходимости preset/type;
- границы, если длительность изменилась.

## Rename Action and Resource Together

Используйте, когда анимация изменила назначение.

Например:

    humanoid_walk → humanoid_walk_tired
    jdh:humanoid_walk → jdh:humanoid_walk_tired

## Copy/Paste Settings

Подходит для серии однотипных движений. Не является копированием poses или markers между несовместимыми шкалами.

## Reset Echo Metadata

Используйте, если Action был настроен совершенно неверно и проще начать описание заново.

Не используйте как способ «починить одну ошибку». Большинство ошибок исправляется конкретным полем или quick fix.

# 25. Горячие клавиши

## Почему они выключены по умолчанию

Клавиши Blender уже часто заняты, а пользовательские keymap могут конфликтовать с другими add-on. Поэтому Echo shortcuts включаются явно.

## Где включить

    Edit → Preferences → Add-ons → Echo Animation Exporter

Включите:

    Enable Echo Marker Shortcuts

Выберите модификатор:

- Alt + Shift;
- Ctrl + Shift.

## Команды

С выбранным модификатором в Action Editor:

- <code>L</code> — Set Loop Start;
- <code>E</code> — Set Loop End;
- <code>H</code> — Hold Pose.

Если shortcut не работает:

1. убедитесь, что курсор находится над Action Editor;
2. убедитесь, что add-on preferences сохранены;
3. проверьте выбранный modifier;
4. проверьте конфликт в Blender Keymap;
5. используйте кнопки панели как надёжную альтернативу.

# 26. Типичные ошибки

## Панель пишет Select an Armature

Выбран меш, камера, свет или другой объект.

Решение: выберите объект Armature в Outliner или 3D Viewport.

## Action: None

У Armature нет активного Action.

Решение: <code>Create Animation</code> или назначить существующий Action через Action Editor.

## После Apply Preset ничего не двигается

Так и должно быть. Preset создаёт описание, не animation keys.

## В Blender цикл хороший, в игре дёргается

Проверьте:

- Loop Seam validation;
- FPS и tick collision;
- фактическую интерполяцию;
- root drift;
- одинаковый Rig;
- crossfade в runtime;
- не проигрывается ли случайно весь Action вместо Loop;
- не включён ли другой канал с конфликтующим движением.

## Ноги двигаются в Blender, но не двигаются в игре

Возможные причины:

- Channel = Upper Body;
- Custom mask не содержит ноги;
- animated bones имеют неправильные имена;
- clip не содержит leg tracks;
- другая анимация владеет нижним каналом.

## Руки сильно сжимаются

Проверьте:

- нет ли scale keys;
- не используется ли неравномерный scale;
- правильные ли локальные вращения;
- корректно ли работает IK;
- не пересекаются ли влияния constraints;
- Validation INFO <code>SCALE_TRACKS</code>.

Не лечите сжатие случайным изменением skin weights, если bind pose и обычная GPU-модель уже корректны.

## NPC едет влево-вправо целиком

Вероятно, анимирован root или body location.

Проверьте:

- root location curves;
- Root Motion mode;
- ROOT_DRIFT;
- какие кости включены в маску.

## NPC стоит на месте при Locomotion

Locomotion animation сама по себе не двигает entity. Нужен locomotion controller.

Если ожидалось root motion, проверьте:

- Extract;
- root track;
- runtime owner;
- интеграцию NPC animation adapter.

## Export ничего не заменяет

Проверьте Overwrite Policy.

При Overwrite Generated Files ручной файл без generated header защищён.

## Export заменил не тот файл

Проверьте:

- Resource ID;
- Resource Folder;
- Output Directory;
- имя активного Action;
- какой Prism instance запущен.

## После смены Action остались старые границы

В норме границы принадлежат Action и должны переключиться. Если вы смотрите обычные Scene Markers, это не Echo source of truth.

Проверьте Action Pose Markers и повторно откройте панель.

## Event есть в файле, но звук не играет

Exporter описал Event, но игровая система должна иметь listener, который связывает это имя с воспроизведением звука.

Уточните:

- точное event name;
- payload;
- зарегистрирован ли listener;
- ожидает ли интеграция Point вместо Event.

## Лицо или второй слой модели выглядит плохо вдали

Это не проблема bone animation metadata. Проверяйте GPU skin renderer, UV, z-fighting, depth offset, mipmaps и shader pipeline отдельно.

Animation exporter не должен использоваться для исправления UV или дистанционного z-fighting.

# 27. Часто задаваемые вопросы

## Нужно ли создавать отдельные Action для Enter, Loop и Exit?

Нет. Для новой работы всё находится в одном Action.

## Можно ли оставить старые три Action?

Для архива — да. Для нового экспорта объедините их через Legacy Migration.

## Preset создаёт готовую ходьбу?

Нет. Он только выставляет тип, канал, состояния и параметры.

## Что выбрать для обычной ходьбы?

Locomotion + Walk Loop.

## Что выбрать для idle?

Loop + Idle Loop.

## Что выбрать для жеста рукой?

One Shot + Upper Body Gesture, если ноги должны продолжать другое движение.

## Что выбрать для смерти?

One Shot + Hold + Death.

## Что выбрать для статичной позы с красивым входом и выходом?

Stateful Hold.

## Почему для статичной позы нельзя сделать Loop в один кадр?

Можно технически пытаться, но смысл неверный и возможны нулевые сегменты после пересчёта в тики. Stateful Hold прямо описывает удержание одного кадра.

## Обязателен ли Enter?

Нет. Он нужен, если авторский вход важен.

## Обязателен ли Exit?

Нет. Без него runtime использует fallback-переход, но результат может быть менее выразительным.

## Обязателен ли Loop?

Для Loop, Stateful Loop и Locomotion — да.

## Нужно ли ставить ключ на Loop Start и Loop End?

Очень желательно. Validation предупредит, а <code>Create Boundary Keys</code> поможет.

## Должны ли Loop Start и Loop End быть одинаковыми?

Для бесшовного цикла — да, в пределах малой численной погрешности по всем экспортируемым костям.

## Первый и последний кадр цикла считаются двумя разными шагами?

Нет. Это две временные позиции с одной и той же позой, образующие шов. Не дублируйте смысловой контакт одной стопы без необходимости.

## Что такое Point простыми словами?

Именованная отметка «вот здесь удобно или безопасно перейти/синхронизироваться».

## Что такое Event простыми словами?

Команда «в этот момент произошло событие», например удар или шаг.

## Payload обязателен?

Нет. Он нужен только интеграции, которая умеет его читать.

## Можно ли перетаскивать Echo markers вручную?

Да. После этого обязательно выполните Validation.

## Можно ли анимировать IK controllers?

Да. Экспортируются вычисленные production bone poses. Validation может сообщить, что control bones сами не экспортируются — это ожидаемо.

## Почему warning не блокирует export?

Потому что часть решений зависит от художественного смысла. Например, одновременный контакт двух ног может быть ошибкой ходьбы, но нормой прыжка.

## Можно ли игнорировать все warnings?

Нет. Каждый warning нужно прочитать и либо исправить, либо осознанно принять.

## Что делать с TICK_COLLISION?

Просмотреть результат в игре. Если теряется важное движение:

- увеличить длительность;
- снизить FPS сцены;
- разнести важные позы дальше;
- не задавать слишком маленький Duration Ticks.

## Нужно ли ставить Engine Tick Rate 20?

Для текущего Minecraft runtime — обычно да.

## Sample Every лучше поставить больше для оптимизации?

Не без измерения. Значение 1 безопаснее для качества.

## Animation Resource и Clip — это одно и то же?

Нет.

- Clip содержит сами bone tracks и временные точки.
- Animation resource описывает, как использовать clip как Enter, Loop, Hold, One Shot и Exit на нужном Channel.

## Какой файл править вручную?

Обычно никакой. Исправляйте Blender Action и экспортируйте заново.

## Почему ручной файл не перезаписывается?

Overwrite Generated Files защищает файл без generated header.

## Можно ли переместить файлы после экспорта?

Можно при сохранении ожидаемой структуры контент-пака, но лучше сразу настроить Output Directory и Resource Folder, чтобы не ошибиться.

## Resource Folder входит в Resource ID?

Нет. Это папка хранения, а не runtime ID.

## Имя Action обязано совпадать с Resource ID?

Не обязано, но согласованные имена значительно уменьшают путаницу.

## Можно использовать кириллицу в Action name?

Blender позволяет, но для pipeline безопаснее латинские имена. Resource ID должен соответствовать строгой допустимой форме и не должен содержать кириллицу.

## Как узнать ID NPC?

Нужен Actor ID, а не отображаемое имя над головой. Его источник зависит от NPC content definition или команды создания NPC. Если неизвестно — уточните у автора контента.

## Почему One Shot не возвращается ровно в idle pose?

Начальная/конечная поза One Shot может не совпадать с текущим idle, а Blender preview не показывает runtime crossfade. Сделайте совместимые крайние позы и проверьте Blend Out в игре.

## Можно ли увидеть crossfade в Blender?

Нет, текущий preview показывает жёсткие phase boundaries. Crossfade проверяется в runtime.

## Extract автоматически двигает NPC?

Нет. Перемещение должен применить runtime locomotion owner.

## Что выбрать, если не понимаю Root Motion?

Disabled и in-place animation.

## Что выбрать, если не понимаю Channel?

Body для full-body движения. Upper Body только когда сознательно хотите сочетать жест с ногами другой анимации.

## Когда нужен Advanced?

Только когда есть конкретное техническое требование к ручным именам lifecycle-сегментов.

## Можно ли экспортировать сразу все Action?

Да, <code>Export All Echo Animations</code>. Invalid Action будут пропущены, остальные продолжат экспорт.

## Batch остановится на первой ошибке?

Нет. Он собирает полный список неудач.

## Старые Action удалятся при миграции?

Нет.

## Можно ли отменить Merge?

Операция поддерживает Undo, а исходные Action сохраняются.

## Где посмотреть сгенерированный EchoScript без записи?

Нажмите <code>Generate Output Preview</code>, затем откройте Blender Text Editor.

## Как доказать программисту, что экспорт верный?

Передайте:

- Resource ID;
- Rig ID;
- тип и Channel;
- validation summary;
- generated clip;
- generated animation resource;
- точную команду проверки;
- screenshot или видео проблемы;
- вывод <code>/echo_animation diagnostics 50</code>.

# 29. Словарь терминов

## Action

Blender datablock, содержащий ключи одной полной Echo-анимации.

## Armature

Объект скелета Blender.

## Bone Track

Экспортированная последовательность трансформаций одной runtime-кости.

## Boundary

Смысловая граница между фазами Action.

## Channel

Часть тела или слой управления, которым владеет анимация.

## Clip

Низкоуровневый ресурс с ключами, сегментами, точками и событиями.

## Enter

Авторский вход из исходного состояния в активное.

## Event

Одноразовый сигнал в конкретном кадре.

## Exit

Авторский выход из активного состояния.

## FPS

Число Blender-кадров в секунду.

## Hold Pose

Один кадр, который runtime удерживает до запроса продолжения или выхода.

## In-place

Анимация шага на месте без перемещения root вперёд.

## Loop

Повторяемый диапазон.

## Loop Seam

Стык конца и начала цикла.

## Marker

Отметка в Action, связанная с boundary, event или point.

## Point

Именованная смысловая точка временной шкалы.

## Preset

Набор метаданных и стандартных настроек, не готовое движение.

## Resource Folder

Папка хранения generated files.

## Resource ID

Уникальный игровой идентификатор вида <code>namespace:path</code>.

## Rig ID

Идентификатор runtime-скелета.

## Root Motion

Перемещение персонажа, закодированное движением root.

## Runtime

Игровая система, которая загружает и проигрывает экспортированные ресурсы.

## Segment

Именованный диапазон общей Action.

## Tick

Шаг игрового времени. В Minecraft обычно 20 тиков в секунду.

## Validation

Автоматическая проверка структуры, временной шкалы, масок и качества loop seam.

# 30. Известные ограничения

## Crossfade не показывается в Blender

Preview показывает фазы и жёсткие переходы. Реальные Blend In, Blend Out и fallback crossfade оцениваются в игре.

## Root Motion не двигает entity самостоятельно

Extract экспортирует данные. Применять их должен locomotion owner.

## Event не является готовой игровой логикой

Exporter записывает Event. Звук, эффект, attachment или сюжетная команда требуют зарегистрированной runtime-интеграции.

## Advanced не является произвольным многоклиповым монтажом

Он позволяет вручную назвать основные lifecycle-сегменты, но модель всё равно строится вокруг одной Action и смысловых Enter/Loop/Hold/Exit.

## Animation exporter не исправляет модель

Проблемы:

- UV;
- skin weights;
- inverse bind;
- vertex attributes;
- GPU shader;
- второй слой скина;
- z-fighting лица;
- mipmaps

относятся к rig/skin/render pipeline, а не к временной разметке анимации.

# Короткая памятка на каждый день

    1. Выбери Armature и правильный Action.
    2. Выбери тип по смыслу, не по названию.
    3. Одна анимация = один Action.
    4. Поставь общие Loop Start и Loop End.
    5. Для Hold используй Hold Pose, а не фальшивый loop.
    6. Для ходьбы добавь контакты обеих стоп и скорость.
    7. Preview нужных фаз.
    8. Validate Animation.
    9. Исправь errors, прочитай warnings.
    10. Generate Output Preview.
    11. Export Active Animation.
    12. Проверь catalog, diagnostics и NPC в Prism.

Если непонятно, какой тип выбрать:

- один раз — One Shot;
- повторять целиком — Loop;
- войти, повторять, выйти — Stateful Loop;
- войти, замереть, выйти — Stateful Hold;
- ходить или бегать — Locomotion;
- один раз и навсегда остаться — One Shot + Hold.


## Системная поза сидения

Action с именем `pose_sit` экспортируется как **Hold** автоматически. Runtime 0.7.1+ читает `jdh:pose_sit_main` как базовую позу для `sitting=true`. Ванильные углы рук/ног больше не накладываются поверх. Если поверх сидящего NPC играет клип только на верх тела, ноги сохраняют `pose_sit`.
# Маркеры предметов в руках

В панели `Events and Points` доступны четыре кнопки с точными runtime ID:
`echo_item_attachments:attach_left_hand`, `echo_item_attachments:attach_right_hand`,
`echo_item_attachments:release`, `echo_item_attachments:detach`. Маркер ставится на текущий
кадр Action и экспортируется в `.animation.es` как `Marker(..., phase: ..., tick: ...)`.
Переименовывать эти четыре ID нельзя: сервер сверяет ID, phase, playback и revision.
